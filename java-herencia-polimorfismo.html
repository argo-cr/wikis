Fundamentos

1. Herencia y polimorfismo

Herencia

Permite definir una nueva clase tomando como base una clase existente. La nueva clase puede reutilizar características comunes y agregar o especializar comportamientos.

Idea clave: normalmente representa una relación “es un”.

Polimorfismo

Permite trabajar con objetos de distintas subclases mediante un tipo común. Aunque la referencia sea de la superclase, cada objeto puede ejecutar su propio comportamiento.

Idea clave: mismo mensaje, comportamientos diferentes.

Ejemplo: un Perro es un Animal; un EmpleadoFijo es un Empleado. Si la frase “es un” no tiene sentido, probablemente la herencia no sea la relación adecuada.

2. Terminología básica

En distintos libros y lenguajes encontrarás varios nombres para referirse a los mismos elementos.

Término recomendado También se conoce como Significado
Superclase Clase padre, clase base Clase general de la cual se heredan características.
Subclase Clase hija, clase derivada Clase especializada que hereda de otra.
Empleado ← Superclase ▲ │ EmpleadoFijo ← Subclase

Una clase puede cumplir ambos papeles. Por ejemplo, si Docente hereda de Empleado y DocenteInterino hereda de Docente, entonces Docente es subclase de Empleado y superclase de DocenteInterino.

3. ¿Cómo se implementa la herencia en Java?

Java utiliza la palabra reservada extends para establecer una relación de herencia entre clases. 

public class Perro extends Animal {

    public Perro(String nombre) {
        super(nombre);
    }
}

extends indica que Perro es una subclase de Animal. Por su parte, super(...) permite llamar al constructor de la superclase.

Importante: los constructores no se heredan. Una subclase puede invocar un constructor de su superclase utilizando super(...).

4. Ejemplo introductorio: Animal

Este ejemplo permite visualizar la herencia con pocas reglas de negocio.

Animal ▲ ▲ │ │ Perro Gato

Superclase

public class Animal {

    private String nombre;

    public Animal(String nombre) {
        this.nombre = nombre;
    }

    public String getNombre() {
        return nombre;
    }

    public void hacerSonido() {
        System.out.println("Sonido de animal");
    }
}

Subclase Perro

public class Perro extends Animal {

    public Perro(String nombre) {
        super(nombre);
    }

    @Override
    public void hacerSonido() {
        System.out.println("Guau");
    }
}

Subclase Gato

public class Gato extends Animal {

    public Gato(String nombre) {
        super(nombre);
    }

    @Override
    public void hacerSonido() {
        System.out.println("Miau");
    }
}
@Override indica que la subclase está proporcionando una nueva implementación de un método heredado. A esto se le llama sobrescritura.

5. Ahora aparece el polimorfismo

Gracias a la relación de herencia, una referencia de tipo Animal puede apuntar a objetos de sus subclases.

Animal animal1 = new Perro("Max");
Animal animal2 = new Gato("Michi");

animal1.hacerSonido(); // Guau
animal2.hacerSonido(); // Miau
Variable Tipo de referencia Objeto real Resultado
animal1 Animal Perro Guau
animal2 Animal Gato Miau

La referencia es del mismo tipo, pero Java ejecuta la versión de hacerSonido() correspondiente al objeto real.

¿Por qué es útil?

Animal[] animales = new Animal[3];

animales[0] = new Perro("Max");
animales[1] = new Gato("Michi");
animales[2] = new Perro("Toby");

for (int i = 0; i < animales.length; i++) {
    animales[i].hacerSonido();
}

No es necesario preguntar si cada objeto es perro o gato. Cada objeto responde de acuerdo con su propia implementación.

Aplicación real

6. Ejemplo: sistema de empleados

En un sistema real podemos tener diferentes tipos de empleados que comparten información, pero calculan su pago de manera diferente.

Empleado ▲ ┌─────────┴──────────────┐ │ │ EmpleadoFijo EmpleadoPorHoras

Superclase Empleado

public class Empleado {

    private String cedula;
    private String nombre;

    public Empleado(String cedula, String nombre) {
        this.cedula = cedula;
        this.nombre = nombre;
    }

    public String getNombre() {
        return nombre;
    }

    public double calcularPago() {
        return 0;
    }
}

Empleado fijo

public class EmpleadoFijo extends Empleado {

    private double salarioMensual;

    public EmpleadoFijo(String cedula, String nombre,
                        double salarioMensual) {
        super(cedula, nombre);
        this.salarioMensual = salarioMensual;
    }

    @Override
    public double calcularPago() {
        return salarioMensual;
    }
}

Empleado por horas

public class EmpleadoPorHoras extends Empleado {

    private int horasTrabajadas;
    private double pagoPorHora;

    public EmpleadoPorHoras(String cedula, String nombre,
                            int horasTrabajadas, double pagoPorHora) {
        super(cedula, nombre);
        this.horasTrabajadas = horasTrabajadas;
        this.pagoPorHora = pagoPorHora;
    }

    @Override
    public double calcularPago() {
        return horasTrabajadas * pagoPorHora;
    }
}

La ventaja del polimorfismo

Empleado[] empleados = new Empleado[3];

empleados[0] = new EmpleadoFijo(
    "1-1111-1111", "Ana", 850000
);

empleados[1] = new EmpleadoPorHoras(
    "2-2222-2222", "Carlos", 120, 4500
);

empleados[2] = new EmpleadoFijo(
    "3-3333-3333", "María", 950000
);

for (int i = 0; i < empleados.length; i++) {
    System.out.println(
        empleados[i].getNombre() + ": ₡" +
        empleados[i].calcularPago()
    );
}
Observa: el ciclo no necesita conocer el tipo específico de empleado. Todos se tratan como Empleado, pero cada objeto ejecuta su propia versión de calcularPago().

7. Tipos de herencia

Herencia simple ✓

Una subclase hereda directamente de una superclase.

class B extends A { }

Herencia multinivel ✓

Una subclase puede convertirse en superclase de otra.

class B extends A { }
class C extends B { }

Herencia múltiple entre clases ✗

Java no permite que una clase extienda directamente más de una clase.

// No es válido en Java
class C extends A, B { }

¿Y si necesito varios comportamientos?

Java permite implementar múltiples interfaces. Ese mecanismo se estudiará posteriormente.

8. Modificadores de acceso

La herencia no elimina las reglas de encapsulamiento.

Modificador Acceso general
private Únicamente dentro de la propia clase.
protected Desde la propia clase, clases del mismo paquete y subclases según las reglas de Java.
public Desde cualquier clase donde el elemento sea visible.
Como regla práctica, conserva los atributos private cuando sea posible y utiliza métodos para controlar el acceso a los datos.

9. Sobrecarga vs. sobrescritura

Los nombres son parecidos, pero representan conceptos diferentes.

Sobrecarga Sobrescritura
Mismo nombre de método. Se redefine un método heredado.
La lista de parámetros debe ser diferente. Mantiene la firma compatible del método.
sumar(int, int)
sumar(double, double)		 @Override calcularPago()
No requiere herencia. Está vinculada con la herencia.

10. En resumen

  1. Herencia: permite crear clases especializadas a partir de otras existentes.
  2. Superclase: clase general. Subclase: clase especializada.
  3. extends establece la herencia entre clases.
  4. super(...) permite invocar un constructor de la superclase.
  5. @Override se utiliza al sobrescribir un método heredado.
  6. Polimorfismo: permite tratar objetos de distintas subclases mediante un tipo común, conservando su comportamiento particular.

Comprueba lo aprendido

Analiza la siguiente instrucción:

Empleado empleado = new EmpleadoFijo(
    "1-1111-1111", "Ana", 850000
);
¿Cuál es la superclase?

Empleado.

¿Cuál es la subclase?

EmpleadoFijo.

¿Cuál es el tipo de la referencia?

Empleado.

¿Cuál es el tipo real del objeto?

EmpleadoFijo.

¿Dónde observamos polimorfismo?

Una referencia de tipo Empleado apunta a un objeto de la subclase EmpleadoFijo. Al invocar un método sobrescrito, se ejecutará la implementación correspondiente al objeto real.
