Objetivo

Comprender un flujo completo, sin complicarlo

Laravel ofrece muchas herramientas, pero para construir un sistema web tradicional primero deben dominar una ruta sencilla: solicitud, controlador, modelo, base de datos y vista.

Navegador
Ruta
Controlador

Trabajaremos con

Rutas resource, controladores, modelos Eloquent, relaciones, validación y vistas Blade.

No necesitamos todavía

Autenticación avanzada, colas, eventos, servicios, repositorios, Docker o una arquitectura SPA.

Base de datos existente

La estructura se administra en MySQL y se conserva mediante un archivo SQL versionado.

Meta de aprendizajeAl finalizar, deben poder explicar qué archivo recibe cada solicitud, dónde se valida, cómo se consulta MySQL y cuál vista presenta el resultado.
1

Definir la versión antes de comenzar

Todos los integrantes del curso deben trabajar con la misma versión principal de Laravel y una versión de PHP compatible. Una diferencia de versiones puede cambiar requisitos, archivos iniciales o comportamiento.

Comprobar herramientas
php -v
composer --version

Después de crear el proyecto:

Comprobar Laravel
php artisan --version
php artisan about
Laravel 13Requiere PHP 8.3 o superior. Si el entorno del curso utiliza otra versión de PHP, el docente indicará la versión de Laravel correspondiente.
No fuerce una instalación incompatibleEvite --ignore-platform-reqs. El proyecto podría instalarse y fallar posteriormente porque PHP o alguna extensión no cumple los requisitos.
2

Crear y ejecutar un proyecto

Opción A: Composer

No requiere instalar globalmente Laravel Installer. Descarga el proyecto y sus dependencias directamente.

Terminal
composer create-project laravel/laravel:^12.0 nombre_proyecto

Se debe descomentar (eliminar el ;) extension=zip en xampp/php/php.ini.

Opción B: Laravel Installer

El primer comando se ejecuta una sola vez en la computadora.

Terminal
composer global require laravel/installer
laravel new nombre_proyecto

Ejecutar localmente

Terminal, dentro del proyecto
cd nombre_proyecto
php artisan serve

El servidor integrado suele quedar disponible en http://localhost:8000. Se utiliza únicamente para desarrollo local.

Con XAMPP y Virtual HostsNo es necesario ejecutar php artisan serve. El DocumentRoot del dominio local debe apuntar a la carpeta public del proyecto.
3

Usar Composer correctamente

Comando Uso correcto ¿Modifica composer.lock?
composer install Instala en vendor las versiones exactas registradas en composer.lock. Úselo después de clonar o descargar. No, si el archivo ya existe.
composer update Busca versiones nuevas permitidas por composer.json. Ejecútelo únicamente cuando se desea actualizar dependencias. Sí.
composer install --no-dev --optimize-autoloader Instala dependencias de producción, omite paquetes de desarrollo y optimiza la carga de clases. No.
composer dump-autoload Regenera el cargador de clases. Puede ayudar después de mover o crear clases manualmente. No.
No utilice update para reparar el proyectocomposer update puede cambiar muchas versiones a la vez. Para reconstruir vendor a partir del proyecto recibido, normalmente corresponde composer install.
En GitSe conserva composer.json y composer.lock. La carpeta vendor normalmente no se versiona.

Configurar .env para MySQL

Laravel reciente inicia normalmente con SQLite. Para utilizar una base MySQL existente, modifique las variables DB_* del archivo .env.

.env · desarrollo local
APP_NAME="Sistema de Personas"
APP_ENV=local
APP_KEY=
APP_DEBUG=true
APP_URL=http://personas.local
APP_LOCALE=es

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=sistema_personas
DB_USERNAME=root
DB_PASSWORD=

SESSION_DRIVER=file
CACHE_STORE=file
QUEUE_CONNECTION=sync
Importante cuando no se usan migracionesLas instalaciones actuales pueden configurar sesiones, caché y colas con el controlador database. Eso requiere tablas adicionales. Para el enfoque de esta guía se utilizarán file y sync.
APP_KEYSi ya contiene una clave, no la cambie. Si está vacía en una instalación nueva, ejecute una sola vez php artisan key:generate.
.env no se comparte en GitCada computadora y cada servidor posee credenciales distintas. Mantenga actualizado .env.example, pero sin contraseñas ni claves reales.
6

Trabajar sin migraciones de forma reproducible

Laravel no obliga a utilizar migraciones. Puede conectarse a tablas ya creadas, pero el proyecto debe conservar una forma clara de reconstruir su estructura.

  1. Cree la base de datos directamente en MySQL o phpMyAdmin.
  2. Defina llaves primarias, foráneas, índices y tipos de datos.
  3. Exporte únicamente la estructura a un archivo SQL.
  4. Guarde el archivo dentro del proyecto y actualícelo cuando cambie el esquema.
  5. Importe ese archivo al preparar otra computadora o servidor.
Organización recomendada
database/
└── sql/
    └── esquema.sql
El archivo SQL reemplaza la función de reproducciónNo debe contener contraseñas ni información real de clientes. Incluya la estructura y, solo cuando sea necesario, datos de catálogo o prueba.
Sobre database/migrationsLos archivos predeterminados pueden permanecer sin utilizar. No ejecute php artisan migrate salvo que el docente lo solicite expresamente.
7

Definir rutas y controlar la navegación

Las rutas reciben una solicitud del navegador y determinan qué respuesta debe generar la aplicación. Se definen principalmente en routes/web.php.

Rutas simples

Una ruta puede devolver texto directamente o cargar una vista Blade.

routes/web.php
use Illuminate\Support\Facades\Route;

Route::get('/', function () {
    return view('inicio');
});

Route::get('/saludo', function () {
    return 'Hola desde Laravel';
});

Rutas con parámetros

Los parámetros permiten recibir valores directamente desde la dirección de la página, como el identificador de una persona.

Parámetro obligatorio
Route::get('/personas/{id}', function ($id) {
    return 'Persona número: ' . $id;
});

También pueden enviarse como parámetros a un método de controlador:

Parámetro en un controlador
Route::get('/personas/{id}', [ControllerPersona::class, 'show'])
    ->name('personas.show');
ControllerPersona.php
public function show($id)
{
    return 'Persona número: ' . $id;
}

Parámetros opcionales

Cuando un parámetro puede omitirse, se agrega un signo de interrogación y se establece un valor predeterminado.

Parámetro opcional
Route::get('/saludo/{nombre?}', function ($nombre = 'estudiante') {
    return 'Hola, ' . $nombre;
});

En este ejemplo funcionan las siguientes direcciones:

  • /saludo
  • /saludo/Olivier

Parámetros de consulta

Los parámetros de consulta se agregan después del signo ?. Son útiles para filtros, búsquedas y paginación.

Ejemplo de URL
/personas?buscar=Ana&orden=asc
Leer parámetros de consulta
use Illuminate\Http\Request;

Route::get('/personas', function (Request $request) {
    $buscar = $request->query('buscar');
    $orden = $request->query('orden', 'asc');

    return view('personas.index', compact('buscar', 'orden'));
});

Rutas manuales hacia un controlador

Cuando una ruta necesita lógica, es preferible enviarla a un método de un controlador.

Crear el controlador
php artisan make:controller ControllerPersona
routes/web.php
use App\Http\Controllers\ControllerPersona;

Route::get('/personas', [ControllerPersona::class, 'index'])
    ->name('personas.index');

Route::get('/personas/crear', [ControllerPersona::class, 'create'])
    ->name('personas.create');

Route::post('/personas', [ControllerPersona::class, 'store'])
    ->name('personas.store');

Route::get('/personas/{id}', [ControllerPersona::class, 'show'])
    ->name('personas.show');
El orden importaColoque rutas específicas como /personas/crear antes de rutas dinámicas como /personas/{id}, para evitar que “crear” sea interpretado como un identificador.

Vinculación automática con modelos

Laravel puede buscar automáticamente un modelo cuando el parámetro de la ruta coincide con el nombre de la variable y el tipo corresponde al modelo.

Route Model Binding
use App\Models\Persona;

Route::get('/personas/{persona}', function (Persona $persona) {
    return view('personas.show', compact('persona'));
});
¿Qué ocurre aquí?Laravel utiliza el valor de {persona} para buscar el registro correspondiente. Si no lo encuentra, devuelve automáticamente una respuesta 404.

Rutas resource para un CRUD

Route::resource genera automáticamente las siete rutas convencionales de un CRUD.

routes/web.php
use App\Http\Controllers\ControllerPersona;

Route::resource('personas', ControllerPersona::class);
Consultar las rutas disponibles
php artisan route:list
Método URL Método del controlador
GET /personas index
GET /personas/create create
POST /personas store
GET /personas/{persona} show
GET /personas/{persona}/edit edit
PUT/PATCH /personas/{persona} update
DELETE /personas/{persona} destroy

Proteger rutas con middleware

El middleware auth permite que una ruta sea accesible únicamente para usuarios autenticados.

Proteger una ruta individual
Route::get('/panel', function () {
    return view('panel');
})->middleware('auth');
Proteger un grupo de rutas
Route::middleware('auth')->group(function () {
    Route::resource('personas', ControllerPersona::class);
    Route::get('/reportes', [ReporteController::class, 'index']);
});
RecomendaciónUse nombres de rutas, controladores para la lógica y middleware para las reglas de acceso. Mantenga las rutas fáciles de leer y evite colocar consultas directamente dentro de los archivos de rutas.

Configurar un modelo

Primero vamos a crear el modelo:

Artisan
php artisan make:model Persona

Laravel supone por convención que el modelo Persona utiliza la tabla personas, una llave primaria llamada id y columnas created_at y updated_at. Solo se cambian las propiedades que no coincidan con esa convención.

app/Models/Persona.php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Persona extends Model
{
    // Omita esta propiedad si la tabla se llama personas.
    protected $table = 'personas';

    // Omita esta propiedad si la llave primaria se llama id.
    protected $primaryKey = 'id_persona';

    // Utilice false solo si estas columnas no existen.
    public $timestamps = false;

}

$fillable

Protege el modelo e indica qué campos pueden asignarse en bloque.

$timestamps

No debe desactivarse por costumbre; hágalo únicamente cuando la tabla no tenga las columnas esperadas.

No use request()->all()Valide los datos y entregue al modelo únicamente el arreglo validado.

Representar relaciones entre tablas

En este ejemplo, un criterio pertenece a un formulario y posee muchos subcriterios.

app/Models/Criterio.php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Relations\BelongsTo;
use Illuminate\Database\Eloquent\Relations\HasMany;

class Criterio extends Model
{
    protected $table = 'criterios';
    protected $primaryKey = 'id_criterio';
    public $timestamps = false;

    public function subcriterios()
    {
        return $this->hasMany(Subcriterio::class, 'id_criterio');
    }

    public function formulario()
    {
        return $this->belongsTo(Formulario::class, 'id_formulario');
    }
}
Acceder a las relaciones
$criterio = Criterio::findOrFail($id_criterio);

$formulario = $criterio->formulario;       // Un modelo o null
$subcriterios = $criterio->subcriterios;   // Una colección
Eloquent sí consulta la base de datosLa ventaja es que no deben escribir manualmente el SQL ni el JOIN. Al acceder a la propiedad, Eloquent carga la relación.

Cargar relaciones junto con el modelo

Carga anticipada
$criterio = Criterio::with(['formulario', 'subcriterios'])
    ->findOrFail($id_criterio);

Esta forma es especialmente útil al recorrer listas, porque evita ejecutar consultas repetidas por cada registro.

Rutas con recursos relacionados

Cuando un criterio debe identificarse dentro de un formulario, puede utilizarse un recurso anidado:

routes/web.php
use App\Http\Controllers\CriterioController;

Route::resource(
    'formularios.criterios',
    CriterioController::class
);

Laravel generará rutas como:

Ruta de edición generada
GET /formularios/{formulario}/criterios/{criterio}/edit

Nombre: formularios.criterios.edit
Controlador con Route Model Binding
public function edit(Formulario $formulario, Criterio $criterio)
{
    return view(
        'criterios.edit',
        compact('formulario', 'criterio')
    );
}
Enlace en Blade
<a href="{{ route(
    'formularios.criterios.edit',
    [$formulario, $criterio]
) }}">
    Editar criterio
</a>
Los nombres deben ser únicosSi Route::resource('criterios', ...) ya creó criterios.edit, no declare otra ruta manual con ese mismo nombre.

Ejemplo de controlador CRUD completo

Este ejemplo utiliza validación, asignación masiva controlada y vinculación automática del modelo.

app/Http/Controllers/ControllerPersona.php
<?php

namespace App\Http\Controllers;

use App\Models\Persona;
use Illuminate\Http\Request;

class ControllerPersona extends Controller
{
    public function index()
    {
        $personas = Persona::orderBy('nombre')->get();

        return view('personas.index', compact('personas'));
    }

    public function create()
    {
        return view('personas.create');
    }

    public function store(Request $request)
    {
        $datos = $this->validar($request);

        Persona::create($datos);

        return redirect()
            ->route('personas.index')
            ->with('success', 'Persona registrada correctamente.');
    }

    public function show(Persona $persona)
    {
        return view('personas.show', compact('persona'));
    }

    public function edit(Persona $persona)
    {
        return view('personas.edit', compact('persona'));
    }

    public function update(Request $request, Persona $persona)
    {
        $datos = $this->validar($request);

        $persona->update($datos);

        return redirect()
            ->route('personas.index')
            ->with('success', 'Persona actualizada correctamente.');
    }

    public function destroy(Persona $persona)
    {
        $persona->delete();

        return redirect()
            ->route('personas.index')
            ->with('success', 'Persona eliminada correctamente.');
    }

    private function validar(Request $request): array
    {
        return $request->validate([
            'nombre' => ['required', 'string', 'max:100'],
            'correo' => ['nullable', 'email', 'max:120'],
            'telefono' => ['nullable', 'string', 'max:30'],
        ]);
    }
}
Route Model BindingEn métodos como edit(Persona $persona), Laravel busca automáticamente el registro utilizando el valor de {persona}. Si no existe, responde con 404.
14

Crear plantillas y reutilizar contenido con Blade

Blade permite crear una plantilla general para conservar elementos comunes, como el menú, el encabezado y el pie de página, mientras cada vista define su propio título y contenido.

Organización recomendada

Las plantillas generales se guardan dentro de resources/views/layouts y los fragmentos reutilizables dentro de resources/views/parts.

Estructura de vistas
resources/views/
├── layouts/
│   └── app.blade.php
├── parts/
│   ├── menu.blade.php
│   ├── header.blade.php
│   └── footer.blade.php
└── personas/
    ├── index.blade.php
    ├── create.blade.php
    └── edit.blade.php

Crear una plantilla general

La plantilla contiene la estructura común del sitio. La directiva @yield define espacios que serán completados por cada vista.

resources/views/layouts/app.blade.php
<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>@yield('titulo', 'Sistema Laravel')</title>
    <link rel="stylesheet" href="{{ asset('css/app.css') }}">
</head>
<body>
    @include('parts.menu')

    <main class="container">
        @include('parts.mensajes')
        @yield('contenido')
    </main>

    @include('parts.footer')
    <script src="{{ asset('js/app.js') }}"></script>
</body>
</html>
@yieldDefine un espacio dentro de la plantilla. Cada vista hija puede colocar contenido allí utilizando @section.

Crear el menú reutilizable

El menú se escribe una sola vez y se incorpora en todas las vistas mediante @include.

resources/views/parts/menu.blade.php
<nav>
    <a href="{{ route('personas.index') }}">Personas</a>
    <a href="{{ route('personas.create') }}">Registrar persona</a>
</nav>

Utilizar la plantilla desde una vista

La directiva @extends indica la plantilla que utilizará la vista. Luego, @section completa los espacios definidos con @yield.

resources/views/personas/index.blade.php
@extends('layouts.app')

@section('titulo', 'Listado de personas')

@section('contenido')
    <h1>Listado de personas</h1>
    <p>En esta sección se muestran las personas registradas.</p>

    <a href="{{ route('personas.create') }}">
        Registrar persona
    </a>
@endsection

Secciones con contenido extenso

Cuando la sección contiene varias líneas, se utiliza la forma de apertura y cierre de @section.

resources/views/personas/create.blade.php
@extends('layouts.app')

@section('titulo', 'Registrar persona')

@section('contenido')
    <h1>Registrar persona</h1>

    <form method="POST" action="{{ route('personas.store') }}">
        @csrf
        <label for="nombre">Nombre</label>
        <input type="text" id="nombre" name="nombre">
        <button type="submit">Guardar</button>
    </form>
@endsection

Incluir archivos parciales

@include permite insertar el contenido de otro archivo Blade dentro de la vista actual. Es útil para menús, encabezados, mensajes y pies de página.

Incluir un archivo parcial
@include('parts.menu')
@include('parts.header')
@include('parts.footer')

Enviar datos a un include

También es posible enviar información específica al archivo incluido.

Incluir un mensaje
@include('parts.alerta', [
    'mensaje' => 'Persona registrada correctamente.',
    'tipo' => 'success'
])
resources/views/parts/alerta.blade.php
<div class="alert alert-{{ $tipo }}">
    {{ $mensaje }}
</div>
Flujo recomendadoUtilice layouts/app.blade.php para la estructura general, @yield para los espacios variables, @section para completar cada vista y @include para reutilizar fragmentos.
No repita el menú en cada vistaAl utilizar un include, se actualiza una sola vez y el cambio se refleja en todas las vistas.
15

Construir formularios Blade correctamente

Registrar

resources/views/personas/create.blade.php
<form method="POST" action="{{ route('personas.store') }}">
    @csrf

    <label for="nombre">Nombre</label>
    <input
        id="nombre"
        name="nombre"
        value="{{ old('nombre') }}"
        required
    >

    @error('nombre')
        <small>{{ $message }}</small>
    @enderror

    <button type="submit">Guardar</button>
</form>

Actualizar

resources/views/personas/edit.blade.php
<form method="POST" action="{{ route('personas.update', $persona) }}">
    @csrf
    @method('PUT')

    <input
        name="nombre"
        value="{{ old('nombre', $persona->nombre) }}"
        required
    >

    <button type="submit">Actualizar</button>
</form>

Eliminar

Formulario de eliminación
<form method="POST" action="{{ route('personas.destroy', $persona) }}">
    @csrf
    @method('DELETE')

    <button type="submit">Eliminar</button>
</form>

@csrf

Debe aparecer en todos los formularios que envían datos.

@method

Permite representar PUT, PATCH y DELETE, que HTML no envía directamente.

old()

Conserva los valores cuando la validación devuelve el formulario.

Un enlace no elimina registrosLa operación destroy debe ejecutarse mediante un formulario con POST, @csrf y @method('DELETE').

Guardar CSS y JavaScript sin Vite

Para mantener el curso simple, los archivos que el navegador necesita directamente pueden guardarse dentro de public. Esta es una estrategia válida sin compilación frontend.

Estructura sugerida
public/
├── css/
│   └── app.css
├── js/
│   └── app.js
├── img/
└── plugins/
Cargar archivos desde Blade
<link rel="stylesheet" href="{{ asset('css/app.css') }}">
<script src="{{ asset('js/app.js') }}" defer></script>
Utilice asset()Genera la URL correcta según la aplicación y evita depender de rutas absolutas como /css/app.css.
Vite existe, pero no es obligatorio aquíLaravel lo ofrece como solución moderna para compilar recursos. Esta guía utiliza archivos directos en public para concentrarse primero en Laravel, PHP y el flujo MVC.

Archivos subidos por usuarios

No confunda recursos propios del sitio con archivos cargados por usuarios. Para archivos públicos administrados por Laravel, se recomienda storage/app/public y el enlace:

Crear enlace público
php artisan storage:link

php artisan make:controller ControllerPersona --resource Crea un controlador resource.
php artisan route:list Muestra las rutas registradas.
php artisan model:show Persona Muestra información detectada sobre el modelo.
php artisan tinker Abre una consola para probar PHP y Eloquent.
php artisan optimize:clear Elimina cachés de optimización y aplicación.
php artisan optimize Genera cachés para producción.
Comandos específicosconfig:clear, route:clear, view:clear y cache:clear sirven para limpiar una caché concreta. Para una limpieza general durante el desarrollo suele bastar optimize:clear.
config:cache es para producciónDurante el desarrollo, los valores de .env cambian con frecuencia. No mantenga la configuración cacheada localmente.

Publicar el proyecto de forma segura

  1. Compruebe que el servidor utiliza una versión compatible de PHP y las extensiones requeridas.
  2. Suba el código sin incluir el archivo .env del entorno local.
  3. Cree o configure el .env propio del servidor.
  4. Instale las dependencias exactas de producción.
  5. Configure el dominio para que apunte únicamente a public.
  6. Verifique permisos de escritura en storage y bootstrap/cache.
  7. Genere las cachés de producción y pruebe el sistema.

Nunca publique la raíz completaEl dominio debe dirigir las solicitudes a proyecto/public/index.php. Mover index.php a la raíz o exponer el proyecto completo puede revelar archivos sensibles.
No borre manualmente las carpetas de cachéNo elimine el contenido de storage/framework/sessions, storage/framework/views ni bootstrap/cache como parte normal del despliegue. Podría cerrar sesiones o eliminar archivos necesarios. Utilice Artisan.
Hosting sin terminalEl proyecto puede funcionar sin php artisan optimize. Si no existe acceso a Composer en el servidor, prepare vendor en un entorno compatible y súbalo junto con el proyecto.

Errores frecuentes y causa probable

Mensaje o situación Qué revisar
419 Page Expired Falta @csrf en el formulario o la sesión no funciona.
POST method is not supported Falta @method('PUT') o @method('DELETE'), o la acción apunta a otra ruta.
MassAssignmentException Revise $fillable y entregue únicamente los datos validados.
Base table or view not found: sessions / cache / jobs Como no se usan migraciones, configure SESSION_DRIVER=file, CACHE_STORE=file y QUEUE_CONNECTION=sync.
Route [...] not defined Ejecute php artisan route:list y compare el nombre exacto.
Unable to prepare route for serialization Puede existir un nombre de ruta duplicado. Todos deben ser únicos.
Unknown database Cree la base, importe esquema.sql y revise DB_DATABASE.
could not find driver Habilite la extensión PDO correspondiente, normalmente pdo_mysql.
Class not found Revise namespace, importación y nombre del archivo; luego pruebe composer dump-autoload.
CSS o JS no carga Use asset() y compruebe que el archivo esté dentro de public.
Error 500 en producción Revise storage/logs/laravel.log, APP_KEY, permisos y compatibilidad de PHP.
No active APP_DEBUG en producciónLos detalles del error pueden mostrar rutas internas, consultas, variables y otros datos sensibles. Consulte el log del servidor.

Lista de comprobación del proyecto

  • Todos trabajan con la misma versión principal de Laravel.
  • PHP y sus extensiones cumplen los requisitos del proyecto.
  • .env utiliza MySQL y contiene las credenciales correctas.
  • Sesiones y caché utilizan file; las colas utilizan sync.
  • .env no se encuentra en Git.
  • La estructura de la base se conserva en database/sql/esquema.sql.
  • Cada modelo configura solamente las convenciones que necesita cambiar.
  • Cada modelo permite sus campos mediante $fillable.
  • Las rutas resource aparecen correctamente en route:list.
  • Los parámetros y variables del Route Model Binding coinciden.
  • Todos los formularios de escritura incluyen @csrf.
  • Actualizar y eliminar utilizan @method.
  • El controlador valida antes de insertar o actualizar.
  • CSS y JavaScript se cargan mediante asset().
  • En producción, APP_DEBUG=false.
  • El dominio del servidor apunta a la carpeta public.
  • storage y bootstrap/cache tienen permisos de escritura.
