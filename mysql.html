01 · Fundamentos

Conceptos fundamentales

Antes de escribir SQL, conviene comprender qué almacenamos y qué software se encarga de administrar esa información.

¿Qué es una base de datos?

Es un conjunto de datos organizados y estructurados de forma ordenada. También puede entenderse como un conjunto de archivos interrelacionados.

Su propósito es permitir que la información pueda consultarse, actualizarse y gestionarse fácilmente.

Sistema Gestor de Bases de Datos (SGBD)

Es el software que permite crear, administrar y manipular bases de datos.

Ejemplos: MySQL, PostgreSQL, SQL Server y Oracle.

Bases de datos relacionales

Organizan la información principalmente mediante tablas, filas y columnas. Las tablas pueden relacionarse entre sí.

Bases de datos no relacionales

Pueden organizar los datos mediante documentos, grafos, pares clave-valor y otras estructuras.

02 · Modelo relacional

Estructura básica de una base de datos relacional

Tabla

Estructura principal que almacena los datos. También puede verse como un archivo. Una base de datos relacional está formada por tablas interrelacionadas.

Fila

Una instancia o entrada que contiene los distintos atributos de un solo elemento. También se conoce como registro.

Columna

Representa un atributo o característica del registro. También se conoce como campo o atributo.

Clave primaria (PK)

Identifica de forma única cada registro y no puede repetirse. Es común utilizar números autogenerados.

id_persona (PK) nombre f_nacimiento género
1 Ana Moraga 1995-02-25 F
3 María Mora 1995-08-12 F
4 Javier Fuentes 2000-10-21 M
Clave foránea (FK): es el campo que permite conectar un registro de una tabla con un registro relacionado de otra tabla. Su valor corresponde a una clave de la tabla referenciada.
03 · Conexiones

Relaciones entre tablas

Uno a uno (1:1)

Una persona solo puede tener un pasaporte y un pasaporte solo pertenece a una persona. La FK puede ubicarse en cualquiera de las dos tablas según el diseño.

Persona↔Pasaporte

Uno a muchos (1:N)

Una persona puede realizar muchos pedidos, pero cada pedido pertenece a una sola persona. La FK se almacena en los pedidos.

Persona→Pedido 1Pedido 2

Muchos a muchos (N:M)

En un proyecto pueden participar muchas personas y una persona puede participar en muchos proyectos. En este caso se crea una tabla intermedia que almacena las claves de las tablas involucradas.

Personas→personas_proyectos←Proyectos

06 · Estructura SQL

Creación de bases de datos y tablas

Crear, seleccionar y eliminar una base de datos

-- Crear base de datos
CREATE DATABASE db_personas;

-- Seleccionar la base de datos
USE db_personas;

-- Eliminar base de datos
DROP DATABASE db_personas;
Los nombres no deben llevar espacios ni tildes. Por convención, se recomienda utilizar minúsculas y guiones bajos.

Crear la tabla personas

CREATE TABLE personas (
    id_persona INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(50),
    apellido VARCHAR(50),
    edad INT
);

AUTO_INCREMENT

Genera automáticamente el valor de id_persona.

PRIMARY KEY

Define la clave que identifica de forma única cada registro.

Crear una tabla con clave foránea

CREATE TABLE telefonos (
    id_telefono INT AUTO_INCREMENT PRIMARY KEY,
    numero VARCHAR(20),
    id_persona INT,
    FOREIGN KEY (id_persona)
        REFERENCES personas(id_persona)
);
FOREIGN KEY (id_persona) establece la relación y REFERENCES personas(id_persona) indica el campo de la tabla padre al que apunta. Si existen registros hijos asociados, el SGBD puede impedir eliminar el registro padre salvo que se defina un comportamiento como ON DELETE CASCADE.

Eliminar tablas

-- Eliminar una tabla específica
DROP TABLE telefonos;

-- Eliminar varias tablas respetando las relaciones
DROP TABLE telefonos, personas;

Cuando existen claves foráneas, normalmente se eliminan primero las tablas hijas y luego las tablas padre.

07 · Operaciones

CRUD con SQL

CREATE · Insertar datos

INSERT INTO personas (nombre, apellido, edad) VALUES
('Ana', 'López', 28),
('Carlos', 'Soto', 34);

No se indica id_persona porque es autogenerado. También es posible insertar varios registros en una misma sentencia.

READ · Consultar datos

-- Todas las personas
SELECT * FROM personas;

-- Filtrar por nombre
SELECT * FROM personas
WHERE nombre = 'Juan Mora';

-- Ordenar por nombre
SELECT * FROM personas
ORDER BY nombre;

-- Combinar personas y teléfonos
SELECT p.nombre, p.apellido, t.numero
FROM personas p
INNER JOIN telefonos t
    ON p.id_persona = t.id_persona;

UPDATE · Actualizar datos

UPDATE personas
SET edad = 29
WHERE id_persona = 1;

UPDATE telefonos
SET numero = '8888-0000'
WHERE id_telefono = 1;

DELETE · Eliminar datos

DELETE FROM telefonos
WHERE id_telefono = 3;

DELETE FROM personas
WHERE id_persona = 2;
Importante: en UPDATE y DELETE, la cláusula WHERE determina cuáles registros se modificarán o eliminarán.
08 · Cierre

Resumen

1. Organizar

La información relacional se estructura en tablas compuestas por filas y columnas.

2. Identificar

La clave primaria identifica registros; la clave foránea permite relacionar tablas.

3. Relacionar

Las relaciones más comunes son 1:1, 1:N y N:M.

4. Manipular

SQL permite crear estructuras y ejecutar las operaciones CRUD sobre los datos.
