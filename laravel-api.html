01

¿Qué es una API REST?

Antes de escribir código, comprendamos qué vamos a construir.

Una API (interfaz de programación de aplicaciones) permite que un programa solicite datos u operaciones a otro. REST es un estilo para diseñar servicios que utilizan los recursos, direcciones URL y métodos de HTTP.

🌐api_clientLaravel · Blade · puerto 8001
HTTP →JSON ←
⚙️api_serverLaravel · API · puerto 8000
↔
🗄️MySQLdb_laravel_api

En un proyecto Laravel tradicional, el controlador suele devolver view('ventas.index'). En una API, devuelve datos JSON; otra aplicación decide cómo presentarlos.

Códigos HTTP útiles

200: operación exitosa · 201: registro creado · 401: no autorizado · 404: recurso inexistente · 422: datos inválidos.

02

Importar la base de datos

La base de datos pertenece al servidor; el cliente nunca se conecta directamente a MySQL.

  1. Inicie MySQL desde su entorno local (por ejemplo, XAMPP).
  2. Abra phpMyAdmin o su gestor SQL preferido.
  3. Importe db_laravel_api.sql, incluido en el ZIP entregado.
  4. Compruebe que exista la base de datos db_laravel_api y la tabla ventas.
  5. Verifique que inicialmente existan ocho registros.
Consulta SQL de verificación
USE db_laravel_api;
SELECT * FROM ventas;
CampoTipo / función
id_ventaINT, llave primaria autoincremental
fechaDATE
clienteVARCHAR(150)
descripcionTEXT
totalDECIMAL(10,2)
Sin migraciones

La estructura y los datos de prueba ya vienen definidos en el SQL. No ejecute php artisan migrate para esta práctica.

03

Ejecutar dos proyectos a la vez

Dos aplicaciones Laravel independientes necesitan puertos diferentes.

  1. Descomprima laravel_api.zip y ubique las carpetas api_server y api_client.
  2. Abra una terminal dentro de cada carpeta.
  3. Ejecute los siguientes comandos y mantenga ambas terminales abiertas.
Terminal A · dentro de api_server
php artisan serve --port=8000
Terminal B · dentro de api_client
php artisan serve --port=8001
DirecciónUso
http://127.0.0.1:8000Servidor API
http://127.0.0.1:8001/ventasInterfaz del cliente
Si faltan dependencias

Ejecute composer install dentro del proyecto correspondiente. Si el archivo .env no existe, cópielo desde .env.example y genere la clave con php artisan key:generate. No comparta credenciales reales.

Trabajaremos sobre el modelo Venta existente; agregaremos la configuración, el controlador y las rutas.

Abra api_server/.env y ajuste las variables de conexión. Sustituya usuario y contraseña según su computadora.

4.2 Completar el modelo existente

El archivo app/Models/Venta.php ya está creado con el nombre de tabla, llave primaria y sin marcas de tiempo. Solo agregaremos $fillable para permitir la creación y actualización masiva de estos cuatro campos.

api_server/app/Models/Venta.php
<?php
namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Venta extends Model
{
    protected $table = 'ventas';
    protected $primaryKey = 'id_venta';
    public $timestamps = false;

    protected $fillable = [
        'fecha', 'cliente', 'descripcion', 'total'
    ];
}

4.3 Habilitar las rutas API

En Laravel 12 el proyecto base no incluye routes/api.php. El comando siguiente instala la infraestructura de API y Sanctum. No utilizaremos autenticación Sanctum en esta práctica; por ahora las rutas estarán abiertas.

Terminal · api_server
php artisan install:api
Atención a las migraciones

Si el instalador pregunta si desea ejecutar migraciones, responda no. Ya importamos nuestra base de datos manualmente. El comando puede instalar Sanctum, pero no necesitamos crear sus tablas para este CRUD sin autenticación.

4.4 Generar un controlador API Resource

Terminal · api_server
php artisan make:controller ControllerVentas --model=Venta --api

La opción --api crea index, store, show, update y destroy. A diferencia de un Resource web, no incluye create ni edit, porque el servidor no muestra formularios.

4.5 Implementar las operaciones CRUD

api_server/app/Http/Controllers/ControllerVentas.php
<?php

namespace App\Http\Controllers;

use App\Models\Venta;
use Illuminate\Http\Request;

class ControllerVentas extends Controller
{
    public function index()
    {
        return response()->json(Venta::all());
    }

    public function store(Request $request)
    {
        $datos = $request->validate([
            'fecha' => 'required|date',
            'cliente' => 'required|string|max:150',
            'descripcion' => 'required|string',
            'total' => 'required|numeric|min:0',
        ]);

        $venta = Venta::create($datos);
        return response()->json($venta, 201);
    }

    public function show($id)
    {
        return response()->json(Venta::findOrFail($id));
    }

    public function update(Request $request, $id)
    {
        $venta = Venta::findOrFail($id);
        $datos = $request->validate([
            'fecha' => 'required|date',
            'cliente' => 'required|string|max:150',
            'descripcion' => 'required|string',
            'total' => 'required|numeric|min:0',
        ]);

        $venta->update($datos);
        return response()->json($venta);
    }

    public function destroy($id)
    {
        $venta = Venta::findOrFail($id);
        $venta->delete();
        return response()->json(['mensaje' => 'Venta eliminada']);
    }
}
¿Por qué validar?

validate() evita guardar datos incompletos o incorrectos. Cuando falla, Laravel responde con estado 422 si la solicitud espera JSON. findOrFail() produce 404 cuando no existe el identificador.

05

Probar la API con Postman

Antes de conectar Laravel, comprobemos que cada endpoint funciona por sí solo.

Descargue Postman desde postman.com/downloads. Cree una colección llamada API Ventas y agregue las solicitudes de la tabla.

MétodoURLResultado esperado
GEThttp://127.0.0.1:8000/api/ventas200 · lista JSON
GEThttp://127.0.0.1:8000/api/ventas/1200 · una venta
POSThttp://127.0.0.1:8000/api/ventas201 · venta creada
PUThttp://127.0.0.1:8000/api/ventas/9200 · venta actualizada (si 9 fue creada)
DELETEhttp://127.0.0.1:8000/api/ventas/9200 · venta eliminada (si 9 fue creada)

5.1 Consultar ventas

Seleccione GET, escriba la URL y presione Send. Observe que la respuesta contiene objetos JSON, no una página HTML.

5.2 Crear una venta

Seleccione POST. En Body → raw → JSON, coloque los siguientes datos. Postman configurará Content-Type: application/json.

POST · Body JSON
{
  "fecha": "2026-11-10",
  "cliente": "Ana López",
  "descripcion": "Venta de accesorios de computadora",
  "total": 24500
}

Revise el código 201 Created y anote el id_venta que devuelve la API. No suponga que siempre será 9: depende del estado de su base de datos.

5.3 Actualizar una venta

Seleccione PUT, use la URL /api/ventas/{id} reemplazando {id} por el identificador real de la venta recién creada. Envíe todos los campos:

PUT · Body JSON
{
  "fecha": "2026-11-10",
  "cliente": "Ana López",
  "descripcion": "Venta de accesorios actualizada",
  "total": 27000
}

5.4 Eliminar una venta

Seleccione DELETE con el mismo identificador. Luego repita GET /api/ventas/{id} y compruebe que ahora responde 404.

Prueba de errores

En Postman agregue Accept: application/json. Pruebe consultar un ID inexistente y enviar un POST sin cliente: deberían aparecer 404 y 422, respectivamente.

✓ Comprobación antes de continuar

El servidor lista, consulta, crea, actualiza y elimina ventas desde Postman, sin depender del proyecto cliente.

Conectar api_client con api_server

El cliente ya tiene vistas Blade y rutas web. No las recrearemos: reemplazaremos únicamente las ventas de prueba y completaremos sus métodos.

En el archivo api_client/.env agregue la URL base del recurso. El cliente no necesita conectarse a MySQL para consultar las ventas.

6.2 Actualizar ControllerVentas

El controlador existente tiene cuatro ventas simuladas en index() y una venta fija en edit(). Sustituiremos ese comportamiento por llamadas HTTP al servidor. Conservamos routes/web.php y las vistas actuales.

api_client/app/Http/Controllers/ControllerVentas.php · reemplazar contenido
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Illuminate\Support\Facades\Http;

class ControllerVentas extends Controller
{
    private function urlApi()
    {
        return config('services.ventas_api_url');
    }

    public function index()
    {
        $respuesta = Http::acceptJson()->get($this->urlApi());
        $respuesta->throw();
        $ventas = $respuesta->object();
        return view('ventas.index', compact('ventas'));
    }

    public function create()
    {
        return view('ventas.create');
    }

    public function store(Request $request)
    {
        $respuesta = Http::acceptJson()->post($this->urlApi(),
            $request->only('fecha', 'cliente', 'descripcion', 'total'));
        $respuesta->throw();
        return redirect()->route('ventas.index');
    }

    public function show($id)
    {
        return redirect()->route('ventas.edit', $id);
    }

    public function edit($id)
    {
        $respuesta = Http::acceptJson()->get($this->urlApi() . '/' . $id);
        $respuesta->throw();
        $venta = $respuesta->object();
        return view('ventas.edit', compact('venta'));
    }

    public function update(Request $request, $id)
    {
        $respuesta = Http::acceptJson()->put($this->urlApi() . '/' . $id,
            $request->only('fecha', 'cliente', 'descripcion', 'total'));
        $respuesta->throw();
        return redirect()->route('ventas.index');
    }

    public function destroy($id)
    {
        $respuesta = Http::acceptJson()->delete($this->urlApi() . '/' . $id);
        $respuesta->throw();
        return redirect()->route('ventas.index');
    }
}

6.3 Entender las líneas importantes

CódigoExplicación
Http::get(...)Solicita el listado o una venta
Http::post(...)Envía los datos de una nueva venta
Http::put(...)Envía cambios de una venta existente
Http::delete(...)Solicita eliminar una venta
->object()Convierte el JSON en objetos; las vistas siguen usando $venta->cliente
->throw()Detiene el flujo si la API devuelve un error HTTP
redirect()->route(...)Vuelve al listado tras guardar, actualizar o eliminar

6.6 Prueba de integración completa

  1. Abra http://127.0.0.1:8001/ventas y verifique que aparecen las ocho ventas de la base de datos (salvo cambios hechos en Postman).
  2. Registre una venta desde la vista Create y compruebe que aparece en el listado.
  3. Abra Editar en una venta distinta de la primera y compruebe que se cargan sus datos correctos.
  4. Actualice sus datos y confirme el cambio.
  5. Elimine la venta creada y compruebe que desaparece.
¿Qué ocurre si se detiene api_server?

El cliente no podrá consultar los datos. Esto demuestra que ahora depende del servicio HTTP. En esta primera práctica throw() muestra el error de Laravel; en una aplicación real conviene manejarlo y presentar mensajes amigables.

✓ Resultado de la práctica guiada

Dos proyectos Laravel independientes, comunicados mediante HTTP/JSON, con un CRUD completo y una única base de datos en el servidor.

07

Desafío: proteger la API con un token fijo

Esta parte se resuelve de manera independiente. No se proporciona la implementación completa.

DESAFÍO PRÁCTICO

¿Puede impedir que una aplicación no autorizada consulte o modifique las ventas?

Actualmente cualquier cliente HTTP que conozca las URLs puede consumir la API. Agregue una credencial compartida que el servidor verifique en cada solicitud.

  1. Defina un token secreto en el .env de api_server. No lo escriba directamente en el controlador ni lo publique en Git.
  2. Cree un middleware que lea el encabezado Authorization: Bearer TOKEN.
  3. Si el token falta o es incorrecto, devuelva JSON con código HTTP 401.
  4. Aplique el middleware a todas las rutas del recurso ventas.
  5. Configure api_client para enviar el token en todas las solicitudes.
  6. Demuestre el funcionamiento en Postman con token válido, token incorrecto y sin token.

Pistas para investigar

Fragmentos de referencia · no son una solución completa
// Leer token del encabezado HTTP:
$request->bearerToken();

// Enviar un token desde el cliente Laravel:
Http::withToken($token)->get($url);

// Responder cuando no se autoriza:
return response()->json(['mensaje' => 'No autorizado'], 401);

Investigue también php artisan make:middleware, config/services.php y cómo asociar un middleware a las rutas de routes/api.php.

PruebaResultado requerido
Sin token401 · JSON de no autorizado
Token incorrecto401 · JSON de no autorizado
Token válidoCRUD funciona desde Postman
Cliente Laravel con tokenCRUD funciona desde las vistas Blade
Límite de esta estrategia

El token fijo es un ejercicio introductorio de protección entre aplicaciones. En producción se requieren HTTPS, gestión segura de credenciales y, según el caso, autenticación individual y revocación de tokens (por ejemplo, Sanctum).
