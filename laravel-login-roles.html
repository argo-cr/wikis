01 · Punto de partida

Continuaremos sobre el proyecto de autenticación local y Google desarrollado en clase. No instalaremos Laravel ni reharemos el login.

👤

↓

Autenticación identifica a la persona que inició sesión. Autorización decide a qué recursos puede acceder. El middleware de rol se encargará de la segunda tarea.

02 · MySQL

Agregar roles a los usuarios

La base de datos debe conocer el tipo de cada usuario para que Laravel pueda comprobar sus permisos.

1

Agregar la columna rol

El valor predeterminado perfil evita que los nuevos registros obtengan privilegios administrativos.

MySQL · tabla usuarios
ALTER TABLE usuarios
ADD COLUMN rol VARCHAR(20) NOT NULL DEFAULT 'perfil';
2

Convertir el primer registro en administrador

Usaremos el usuario con id_usuario = 1 como administrador de esta práctica.

MySQL · actualización del administrador
UPDATE usuarios
SET nombre = 'Administrador',
    user = 'admin',
    correo = 'admin@gmail.com',
    rol = 'admin'
WHERE id_usuario = 1;
3

Comprobar los datos

Confirma que solo el usuario indicado tenga el rol admin y que el resto tenga perfil.

MySQL · verificación
SELECT id_usuario, nombre, user, correo, rol
FROM usuarios
ORDER BY id_usuario;
Importante

La consulta UPDATE no cambia la contraseña. Utiliza la contraseña que ya tenía el registro 1. Si ese registro estaba vinculado a Google, cambiar el correo no borra su identificador de Google.

03 · Eloquent

Revisar el modelo User

El modelo conecta la tabla personalizada usuarios con Laravel Auth y permite consultar los comentarios de cada persona.

1

Revisar la configuración existente

En app/Models/User.php verifica que estén estas propiedades y la relación. No hace falta crear otro modelo.

app/Models/User.php · fragmento
protected $table = 'usuarios';
protected $primaryKey = 'id_usuario';
public $timestamps = false;

public function comentarios()
{
    return $this->hasMany(Comentario::class, 'id_usuario');
}
Comprueba / comprende

El campo rol se lee directamente desde el modelo. No es necesario añadirlo a $fillable para esta práctica: el rol se asigna mediante SQL y no debe aceptarse desde el registro público.

04 · Concepto central

Crear MiddlewareRol

El middleware intercepta la solicitud antes de ejecutar el controlador. Si el rol no coincide, detiene el proceso con un error 403.

1

Generar la clase con Artisan

Artisan crea el archivo con la estructura básica de un middleware.

Terminal
php artisan make:middleware MiddlewareRol
2

Implementar el método handle()

El parámetro $rol permite usar el mismo middleware para distintas secciones de la aplicación.

app/Http/Middleware/MiddlewareRol.php
<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class MiddlewareRol
{
    /**
     * Handle an incoming request.
     *
     * @param  Closure(Request): (Response)  $next
     */
    public function handle(Request $request, Closure $next, string $rol): Response {

        if ($request->user()->rol !== $rol) {
            abort(403);
        }

        return $next($request);
    }
}

Lectura guiada del código

$requestContiene la solicitud HTTP y permite obtener el usuario autenticado mediante user().
$rolRecibe el valor enviado desde la ruta: perfil o admin.
!==Compara estrictamente el rol del usuario con el rol requerido.
abort(403)Detiene la solicitud por falta de permisos (Forbidden).
$next($request)Permite que la solicitud continúe hacia el controlador cuando la validación se cumple.
3

Registrar el alias en Laravel 12

El alias rol permite invocar la clase desde las rutas sin escribir su nombre completo.

bootstrap/app.php · fragmento
use App\Http\Middleware\MiddlewareRol;

// Dentro de ->withMiddleware(function (Middleware $middleware) { ... })
$middleware->alias([
    'rol' => MiddlewareRol::class,
]);
Importante

En Laravel 12 este alias se configura en bootstrap/app.php.

Comprueba / comprende

El middleware usa $request->user()->rol porque las rutas protegidas ejecutan primero auth. Sin autenticación previa, podría no existir un usuario.

05 · Organización

Separar las rutas por nivel de acceso

Las rutas compartidas requieren sesión iniciada. Las exclusivas añaden el middleware parametrizado con el rol correspondiente.

1

Actualizar routes/web.php

Conserva las rutas de invitado del login y Google; reorganiza las rutas autenticadas en tres grupos.

routes/web.php · configuración completa
<?php

use App\Http\Controllers\ControllerAuth;
use App\Http\Controllers\ControllerComentarios;
use App\Http\Controllers\ControllerNavigation;
use App\Http\Controllers\ControllerUsuarios;
use Illuminate\Support\Facades\Route;

// RUTAS INVITADO
Route::middleware('guest')->group(function () {

    Route::get('/login', [ControllerNavigation::class, 'login'])->name('login');
    Route::get('/register', [ControllerNavigation::class, 'register'])->name('register');

    Route::post('/login', [ControllerAuth::class, 'login']);
    Route::post('/register', [ControllerAuth::class, 'register']);

    Route::get('/auth/google', [ControllerAuth::class, 'redirectGoogle'])->name('google');
    Route::get('/auth/google/callback', [ControllerAuth::class, 'callbackGoogle']);
});


// RUTAS COMPARTIDAS
Route::middleware('auth')->group(function () {
    Route::get('/', [ControllerNavigation::class, 'dashboard'])->name('dashboard');
    Route::post('/logout', [ControllerAuth::class, 'logout'])->name('logout');
});


// RUTAS EXCLUSIVAS DEL PERFIL
Route::middleware(['auth', 'rol:perfil'])->group(function () {
    Route::resource('comentarios', ControllerComentarios::class);
});


// RUTAS EXCLUSIVAS DEL ADMINISTRADOR
Route::middleware(['auth', 'rol:admin'])->prefix('admin')->name('admin.')->group(function () {
    Route::resource('usuarios', ControllerUsuarios::class)->only(['index', 'destroy']);
});

¿Por qué está escrito así?

guestRestringe login y registro a visitantes que aún no iniciaron sesión.
authExige una sesión autenticada; lo usan ambos roles para dashboard y logout.
rol:perfilEnvía la cadena perfil al parámetro $rol de MiddlewareRol.
rol:adminEnvía admin y bloquea el acceso a perfiles comunes.
prefix('admin')Añade /admin a las URL de ese grupo.
name('admin.')Añade el prefijo admin. a los nombres de las rutas.
only(['index','destroy'])Evita crear rutas de edición y registro que no necesita la administración.
RutaPerfilAdmin
GET /✓✓
/comentarios✓403
GET /admin/usuarios403✓
DELETE /admin/usuarios/{usuario}403✓

06 · Backend

Administrar usuarios desde un controlador

El administrador necesita solamente dos operaciones: mostrar usuarios con sus cantidades de comentarios y eliminar un usuario con sus comentarios.

1

Crear ControllerUsuarios

Utiliza Artisan para generar el controlador; después implementa los métodos necesarios.

Terminal
php artisan make:controller ControllerUsuarios
2

Implementar index() y destroy()

Este es el código utilizado en la versión actualizada del proyecto. Los métodos vacíos generados por Artisan pueden omitirse.

app/Http/Controllers/ControllerUsuarios.php
<?php

namespace App\Http\Controllers;

use App\Models\User;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\DB;

class ControllerUsuarios extends Controller
{
    public function index()
    {
        $data = User::where('id_usuario', '!=', Auth::id())
            ->withCount('comentarios')
            ->orderBy('nombre')
            ->get();

        return view('modules.admin.usuarios.index', compact('data'));
    }

    public function destroy(User $usuario)
    {
        if ($usuario->id_usuario === Auth::id()) {
            abort(403);
        }

        DB::transaction(function () use ($usuario) {
            $usuario->comentarios()->delete();
            $usuario->delete();
        });

        return redirect()->route('admin.usuarios.index');
    }
}

Claves del controlador

Auth::id()Devuelve la llave primaria del usuario autenticado; en este proyecto es id_usuario.
where('!=', ...)Excluye del listado al administrador que está utilizando el sistema.
withCount()Agrega comentarios_count a cada usuario sin recuperar todos sus comentarios.
User $usuarioLaravel busca el registro automáticamente mediante Route Model Binding.
DB::transaction()Ejecuta ambas eliminaciones como una sola operación: si falla una, se revierte la transacción.
Importante

La ruta generada usa {usuario}, por eso el argumento debe llamarse $usuario, no $user. El modelo debe conservar protected $primaryKey = "id_usuario";.

Comprueba / comprende

La versión mostrada excluye al administrador actual, no a todos los administradores. Si deseas que solamente se puedan eliminar usuarios con rol perfil, añade una comprobación $usuario->rol !== "perfil" en destroy() y filtra index() por ese rol.

07 · Interfaz

Crear la vista y adaptar el menú

La interfaz administrativa muestra el resultado de la consulta y envía una solicitud DELETE al seleccionar un usuario.

1

Crear el index administrativo

Crea la carpeta resources/views/modules/admin/usuarios y dentro el archivo index.blade.php.

resources/views/modules/admin/usuarios/index.blade.php
@extends('app')
@section('titulo', 'Administración de perfiles')
@section('contenido')

<table class="table table-bordered table-striped">
    <thead>
        <tr>
            <th>Nombre</th>
            <th>Usuario</th>
            <th>Correo</th>
            <th>Comentarios</th>
            <th>Acciones</th>
        </tr>
    </thead>

    <tbody>
        @foreach($data as $item)
            <tr>
                <td>{{ $item->nombre }}</td>
                <td>{{ $item->user }}</td>
                <td>{{ $item->correo }}</td>
                <td>{{ $item->comentarios_count }}</td>
                <td>
                    <form method="POST"
                          action="{{ route('admin.usuarios.destroy', $item) }}"
                          onsubmit="return confirm('¿Eliminar este usuario y todos sus comentarios?')">

                        @csrf
                        @method('DELETE')

                        <button class="btn btn-danger btn-sm">
                            Eliminar
                        </button>
                    </form>
                </td>
            </tr>
        @endforeach
    </tbody>
</table>

@endsection

Elementos que debes reconocer

comentarios_countEs el campo calculado por withCount('comentarios').
@csrfAgrega la protección CSRF al formulario.
@method('DELETE')Permite enviar una solicitud DELETE desde un formulario HTML que usa POST.
route(..., $item)Genera la URL del usuario que se desea eliminar.
2

Mostrar opciones según el rol

En el menú principal de resources/views/app.blade.php, conserva Dashboard y añade enlaces condicionales.

resources/views/app.blade.php · fragmento
<a class="nav-link" href="{{ route('dashboard') }}">Dashboard</a>

@if (Auth::user()->rol === 'perfil')
    <a class="nav-link" href="{{ route('comentarios.index') }}">
        Comentarios
    </a>
@endif

@if (Auth::user()->rol === 'admin')
    <a class="nav-link" href="{{ route('admin.usuarios.index') }}">
        Administrar perfiles
    </a>
@endif
Comprueba / comprende

La confirmación con confirm() evita clics accidentales, pero no sustituye la validación del servidor. El método destroy() vuelve a comprobar que el administrador no se elimine a sí mismo.

08 · Protección de registros

Proteger los comentarios propios

El middleware comprueba el rol del usuario; además, el controlador debe comprobar que el comentario solicitado realmente le pertenezca.

1

Crear una validación privada

Añade este método al final de ControllerComentarios, dentro de la clase.

ControllerComentarios.php · método privado
private function validar_usuario(Comentario $comentario)
{
    if ($comentario->id_usuario !== Auth::id()) {
        abort(403);
    }
}
2

Invocar la validación antes de operar

Añade la llamada al inicio de edit(), update() y destroy().

ControllerComentarios.php · métodos modificados
public function edit(Comentario $comentario)
{
    $this->validar_usuario($comentario);
    return view('modules.comentarios.edit', compact('comentario'));
}

public function update(Request $request, Comentario $comentario)
{
    $this->validar_usuario($comentario);
    $comentario->texto = $request->texto;
    $comentario->save();
    return redirect()->route('comentarios.index');
}

public function destroy(Comentario $comentario)
{
    $this->validar_usuario($comentario);
    $comentario->delete();
    return redirect()->route('comentarios.index');
}
Importante

Sin esta comprobación, un usuario de tipo perfil podría intentar modificar el identificador de un comentario en la URL. rol:perfil le permite entrar al módulo, pero no le da permiso para editar comentarios ajenos.

Comprueba / comprende

Mejora opcional: validar texto en store() y update() mediante $request->validate(["texto" => "required|string|max:1000"]);.
