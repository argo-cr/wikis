Parte I · Fundamentos de sockets

1. ¿Qué es un socket?

Un socket es un punto de comunicación entre dos programas. En un modelo cliente-servidor, el servidor abre un puerto y espera conexiones; el cliente conoce la dirección del servidor y solicita conectarse.

CLIENTE SERVIDOR Socket(host, 5000) ───── conexión TCP ─────► ServerSocket(5000) │ └── accept()
Servidor
Escucha conexiones y atiende solicitudes.
Cliente
Inicia la conexión con el servidor.
TCP
Mantiene una conexión confiable y ordenada.

2. Dirección IP y puerto

Para encontrar un servicio en la red necesitamos dos datos: la IP identifica el equipo y el puerto identifica la aplicación o servicio dentro de ese equipo.

192.168.1.25 : 5000 ──────────── ──── IP Puerto

127.0.0.1 y localhost representan el propio equipo. Son ideales para probar cliente y servidor en la misma computadora. Para conectarse desde otra computadora de la red local se utiliza normalmente la IPv4 local del equipo servidor.

Importante: el puerto usado por el programa debe estar disponible. Además, para conexiones desde otros equipos, el firewall puede requerir autorización para Java o para el puerto utilizado.

3. ¿Cómo consultar la IP de la computadora?

En Windows, abre Símbolo del sistema (CMD) o Terminal y ejecuta:

BASH
ipconfig

Busca el adaptador que estés utilizando —Wi-Fi o Ethernet— y localiza Dirección IPv4. Un valor típico podría ser 192.168.1.25.

Escenario Host utilizado por el cliente
Cliente y servidor en la misma PC 127.0.0.1 o localhost
Equipos distintos en la misma red IPv4 local del equipo servidor, por ejemplo 192.168.1.25

5. Enviar objetos: Serializable

En estos proyectos no enviamos únicamente texto: enviamos objetos Mensaje. Para que Java pueda convertir el objeto a bytes y reconstruirlo en el otro extremo, la clase implementa Serializable.

JAVA
public class Mensaje implements Serializable {

    private static final long serialVersionUID = 1L;

    private String usuario;
    private String texto;

    public Mensaje(String usuario, String texto) {
        this.usuario = usuario;
        this.texto = texto;
    }

    public String getUsuario() {
        return usuario;
    }

    public String getTexto() {
        return texto;
    }

    @Override
    public String toString() {
        return usuario + ": " + texto;
    }
}

6. Primer proyecto: Sockets-Basic

El objetivo del primer proyecto es comprender una comunicación sencilla: el servidor espera una conexión, recibe un Mensaje, responde y continúa esperando hasta completar una cantidad determinada de conexiones.

Server básico

JAVA
public class Server extends Thread {

    private int conexiones;

    public Server(int conexiones) {
        this.conexiones = conexiones;
    }

    public void run() {

        try {

            // ABRIR SERVIDOR
            ServerSocket server = new ServerSocket(5000);

            for (int i = 0; i < conexiones; i++) {

                System.out.println("\nEsperando conexión...");

                Socket client = server.accept();

                ObjectOutputStream out =
                    new ObjectOutputStream(client.getOutputStream());
                ObjectInputStream in =
                    new ObjectInputStream(client.getInputStream());

                // RECIBIR MENSAJE
                Mensaje msj = (Mensaje) in.readObject();    
                System.out.println(msj);

                // ENVIAR MENSAJE
                out.writeObject(
                    new Mensaje("Servidor",
                    "Bienvenido " + msj.getUsuario())
                );
                out.flush();

                // ESPERAMOS 1 SEGUNDO
                sleep(1000);
            }

            // CERRAR SERVIDOR
            server.close();

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
Idea clave: accept() bloquea el hilo del servidor hasta que llega una conexión. Por eso el servidor se ejecuta mediante start() en un hilo independiente.

Client básico

JAVA
public class Client {

    private int id;

    public Client(int id) {
        this.id = id;
    }

    public void init() {

        try {

            // ABRIR LA CONEXIÓN

            ObjectInputStream in =
                new ObjectInputStream(client.getInputStream());

            out.writeObject(

            );
            out.flush();

            // RECIBIR MENSAJE
            Mensaje msj = (Mensaje) in.readObject();
            System.out.println(msj);

            // CERRAR LA CONEXIÓN
            client.close();

        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}

Arranque del ejercicio

JAVA
public void init() {

    int conexiones = 3;

    // El servidor se ejecuta en un hilo independiente.
    new Server(conexiones).start();

    // Los clientes se conectan de forma secuencial.
    for (int i = 0; i < conexiones; i++) {
        new Client(i + 1).init();
    }
}

En esta primera versión los clientes se ejecutan uno después de otro. El propósito todavía no es mantener muchos usuarios conversando simultáneamente, sino entender conexión, envío, recepción y cierre.

Parte II · Multichat con hilos

7. ¿Qué problema debemos resolver?

Un chat necesita mantener varios clientes conectados al mismo tiempo. Si el servidor atendiera completamente a un cliente antes de aceptar al siguiente, un usuario podría bloquear a todos los demás.

SERVER │ accept() │ ┌────────────┼────────────┐ ▼ ▼ ▼ ClientHandler ClientHandler ClientHandler │ │ │ Cliente 1 Cliente 2 Cliente 3

La solución es que Server se concentre en aceptar conexiones y entregue cada conexión a un ClientHandler, que se ejecuta en su propio hilo.

8. Server: aceptar conexiones

El servidor mantiene un while(true). Cada vez que accept() retorna un nuevo Socket, se crea un manejador específico para ese cliente.

JAVA
public class Server extends Thread {

    private static final int PORT = 5000;
    private ServerSocket server;

    private static List<ClientHandler> clients =
        Collections.synchronizedList(new ArrayList<>());

    public void run() {

        try {

            server = new ServerSocket(PORT);
            System.out.println("Servidor iniciado...");

            while (true) {

                Socket client = server.accept();
                System.out.println("Cliente: " + client);

                ClientHandler ch = new ClientHandler(client);

                // Registrar antes de iniciar el hilo.
                clients.add(ch);
                ch.start();
            }

        } catch (Exception e) {
            e.printStackTrace();
        }
    }

    public static class ClientHandler extends Thread {

        private Socket client;
        public ObjectOutputStream out;
        public ObjectInputStream in;

        public ClientHandler(Socket client) {
            this.client = client;
        }

        public void run() {

            try {

                out = new ObjectOutputStream(client.getOutputStream());
                in = new ObjectInputStream(client.getInputStream());

                while (true) {
                    Mensaje m = (Mensaje) in.readObject();
                    broadcast(m);
                }

            } catch (Exception e) {
                e.printStackTrace();

            } finally {

                try {
                    client.close();
                } catch (Exception e) {}

                clients.remove(this);
            }
        }

        public void broadcast(Mensaje m) {

            synchronized (clients) {
                for (ClientHandler c : clients) {
                    try {
                        c.out.writeObject(m);
                        c.out.flush();
                    } catch (Exception e) {
                        e.printStackTrace();
                    }
                }
            }
        }
    }
}
Separación de responsabilidades: Server acepta conexiones; ClientHandler conversa con un cliente; broadcast() distribuye los mensajes.

9. ClientHandler: un hilo por cliente

ClientHandler representa una conexión activa. Como extiende Thread, cada cliente puede quedarse esperando en readObject() sin detener a los demás.

ClientHandler #1 ── readObject() ── Cliente 1 ClientHandler #2 ── readObject() ── Cliente 2 ClientHandler #3 ── readObject() ── Cliente 3 Cada línea puede avanzar de manera independiente.

Cuando un cliente envía un mensaje, su manejador lo recibe y llama a broadcast(m). Si la conexión termina, el bloque finally cierra el socket y elimina ese manejador de la lista.

10. La lista de ClientHandler

El servidor necesita recordar quiénes están conectados. Por eso mantiene una lista compartida:

JAVA
private static List<ClientHandler> clients =
    Collections.synchronizedList(new ArrayList<>());

Cada elemento no es solamente un “usuario”: es un objeto que conserva el Socket y los streams necesarios para comunicarse con ese cliente.

clients │ ├── ClientHandler #1 ──► Socket + out + in ├── ClientHandler #2 ──► Socket + out + in └── ClientHandler #3 ──► Socket + out + in

Cuando entra una conexión:

JAVA
ClientHandler ch = new ClientHandler(client);
clients.add(ch);
ch.start();

Cuando se desconecta:

JAVA
clients.remove(this);
Concurrencia: synchronizedList protege operaciones individuales como add() y remove(). Al recorrer la lista, es recomendable sincronizar explícitamente el bloque de iteración, como se muestra en broadcast().

11. Broadcast: enviar a todos

El servidor recibe un mensaje desde un cliente y recorre los manejadores conectados. A través del ObjectOutputStream de cada uno, reenvía el mismo objeto.

JAVA
public void broadcast(Mensaje m) {

    synchronized (clients) {

        for (ClientHandler c : clients) {

            try {
                c.out.writeObject(m);
                c.out.flush();

            } catch (Exception e) {
                e.printStackTrace();
            }
        }
    }
}
Cliente A │ │ Mensaje("Ana", "Hola") ▼ ClientHandler A │ ▼ broadcast() │ ├────────► ClientHandler A ──► Cliente A ├────────► ClientHandler B ──► Cliente B └────────► ClientHandler C ──► Cliente C

12. Client: enviar y escuchar al mismo tiempo

El cliente del multichat también extiende Thread. Su hilo queda escuchando mensajes entrantes, mientras la interfaz gráfica puede seguir respondiendo a los botones del usuario.

JAVA
public class Client extends Thread {

    private static final int PORT = 5000;

    private ViewChat v;

    private Socket client;
    private ObjectOutputStream out;
    private ObjectInputStream in;

    public Client(ViewChat v, String host) {
        this.v = v;

        try {
            client = new Socket(host, PORT);
        } catch (Exception e) {
            e.printStackTrace();
        }
    }

    public void run() {

        try {

            out = new ObjectOutputStream(client.getOutputStream());
            in = new ObjectInputStream(client.getInputStream());

            while (true) {

                Mensaje m = (Mensaje) in.readObject();

                if (v != null) {
                    v.appendMessage(m.toString());
                }
            }

        } catch (Exception e) {
            e.printStackTrace();
        }
    }

    public void send(Mensaje m) {

        try {

            out.writeObject(m);
            out.flush();

            v.clearSend();

        } catch (Exception e) {
            e.printStackTrace();
        }
    }

    public void close() {

        try {
            out.close();
            in.close();
            client.close();
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}

El método run() se dedica a recibir. El método send() se invoca cuando el usuario desea enviar. Esa separación hace posible que el chat reciba mensajes incluso cuando el usuario no está haciendo nada.

Conexión desde el controlador

v.btnConectar.addActionListener(e -> {

13. Flujo completo del multichat

1. MainServer │ ▼ Server.start() │ ▼ ServerSocket(5000) │ │ accept() ▼ 2. Llega Client A ─────► ClientHandler A.start() │ │ accept() ▼ 3. Llega Client B ─────► ClientHandler B.start() 4. Client A: send(Mensaje) │ ▼ ClientHandler A: readObject() │ ▼ broadcast(Mensaje) │ ├────────► A └────────► B 5. Cada Client.run() recibe el objeto y actualiza su ViewChat.
Server
Acepta nuevas conexiones. No debería quedarse atendiendo personalmente a un único usuario.
ClientHandler
Atiende permanentemente a un cliente específico y participa en el broadcast.
Client
Mantiene la conexión, escucha mensajes y proporciona send().
clients
Representa el conjunto de conexiones activas que pueden recibir mensajes.
