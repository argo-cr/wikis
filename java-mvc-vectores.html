Modelo–Vista–Controlador usando vectores

Guía práctica basada en el proyecto Cuenta Bancaria. El objetivo es comprender cómo se distribuyen las responsabilidades entre las clases y cómo el controlador administra objetos almacenados en un vector.

Concepto

1. ¿Qué es MVC?

MVC divide un programa en tres responsabilidades. En vez de colocar datos, menú, lectura del teclado y lógica en una sola clase, cada parte tiene un propósito específico.

Modelo

Representa los datos y el comportamiento del objeto del mundo real. En este proyecto es CuentaBancaria.

Vista

Se comunica con el usuario: muestra títulos, mensajes y menús, y solicita información mediante Scanner.

Controlador

Coordina el programa. Recibe lo que pide la vista, administra el vector y decide qué operación realizar.

Modelo

3. El Modelo: CuentaBancaria

El modelo describe qué información tiene una cuenta. Sus atributos son privados y se accede a ellos mediante métodos.

public class CuentaBancaria {
    private String titular;
    private int saldo, interes;

    public CuentaBancaria(String titular, int saldo, int interes) {
        this.titular = titular;
        this.saldo = saldo;
        this.interes = interes;
    }
}

El modelo también puede contener comportamiento propio de una cuenta, por ejemplo calcular y aplicar su interés.

public void aplicarInteres() {
    saldo += calcularInteres();
}

public int calcularInteres() {
    int monto = (saldo * interes) / 100;
    return monto;
}
Idea clave: una instancia de CuentaBancaria representa una cuenta. El vector del controlador permitirá guardar muchas instancias de este modelo.
Vista

4. La Vista: comunicación con el usuario

La vista concentra la interacción por consola. Por eso posee el Scanner. 

private Scanner entrada;

public Vista() {
    entrada = new Scanner(System.in);
}

Mostrar información

public void mostrarMensaje(String texto) {
    System.out.println(texto);
}

public void mostrarTitulo(String titulo) {
    System.out.println("\n===== " + titulo + " =====");
}

Solicitar información

public int pedirOpcion() {
    System.out.print("Opción: ");
    int opcion = entrada.nextInt();
    entrada.nextLine();
    return opcion;
}

La vista retorna el dato al controlador. No decide qué hacer con la opción; esa decisión corresponde al controlador.

Solicitar los datos de una cuenta

public CuentaBancaria registrarCuenta() {
    System.out.print("Titular: ");
    String titular = entrada.nextLine();

    System.out.print("Saldo: ");
    int saldo = entrada.nextInt();
    entrada.nextLine();

    System.out.print("Interés: ");
    int interes = entrada.nextInt();
    entrada.nextLine();

    return new CuentaBancaria(titular, saldo, interes);
}
Observe: la vista obtiene tres datos, construye un objeto y lo devuelve. Todavía no lo guarda en el vector.
Controlador

5. El Controlador: coordinador de la aplicación

El controlador conoce la vista y administra la colección de modelos.

private Vista v;
private CuentaBancaria[] cuentas;
private int registros;

public Controlador() {
    v = new Vista();
    registros = 0;
}

Estas tres variables cumplen funciones distintas: v permite comunicarse con el usuario; cuentas almacena objetos; y registros controla cuántas posiciones del vector están ocupadas.

6. ¿Cómo maneja el controlador el vector?

cuentas = new CuentaBancaria[100];

Esta instrucción crea espacio para 100 referencias a objetos CuentaBancaria. Eso no significa que ya existan 100 cuentas. Inicialmente las posiciones están vacías.

0Oli
1Ana
2Luis
3María
4null
...vacío
99null

Si hay cuatro objetos guardados, entonces registros == 4. La siguiente cuenta debe colocarse en cuentas[4].

cuentas[registros++] = new CuentaBancaria("Oli", 5000, 10);

El operador ++ usa primero el valor actual de registros como índice y después lo aumenta en uno. Es equivalente a:

cuentas[registros] = new CuentaBancaria("Oli", 5000, 10);
registros++;
Importante: para recorrer las cuentas registradas se utiliza i < registros, no i < cuentas.length. cuentas.length vale 100 aunque la mayoría de posiciones todavía estén vacías.

7. Registrar: de la Vista al vector

public void registrar() {
    v.mostrarTitulo("REGISTRAR CUENTA");
    CuentaBancaria cuenta = v.registrarCuenta();
    cuentas[registros++] = cuenta;
    v.mostrarMensaje("Cuenta registrada: " + cuenta.getTitular());
}

Este método permite ver claramente la coordinación del MVC:

Paso Qué ocurre
1 El controlador solicita a la vista mostrar el título.
2 La vista pide titular, saldo e interés y devuelve un CuentaBancaria.
3 El controlador recibe ese objeto.
4 El controlador lo guarda en la posición indicada por registros.
5 registros aumenta y queda preparado para el próximo registro.
6 La vista muestra la confirmación al usuario.

8. Recorrer el vector y consultar información

Para procesar todas las cuentas registradas se utiliza un for.

for (int i = 0; i < registros; i++) {
    v.mostrarMensaje(cuentas[i].toString());
}

En cada repetición, cuentas[i] representa un objeto distinto del vector. Desde ese objeto se pueden invocar getters o métodos del modelo.

Ejemplo: acumular el saldo

int total = 0;

for (int i = 0; i < registros; i++) {
    total += cuentas[i].getSaldo();
}

v.mostrarMensaje("Saldo: " + total);

Ejemplo: seleccionar una cuenta

int index = v.pedirOpcion();
CuentaBancaria cuenta = cuentas[index - 1];
v.mostrarMensaje(cuenta.toString());

Al usuario se le muestran números desde 1, pero los vectores comienzan en 0. Por eso se utiliza index - 1.

9. ¿Dónde va el menú?

La presentación del menú pertenece a la Vista, porque es información que se muestra al usuario.

public void mostrarMenuPrincipal() {
    mostrarTitulo("MENÚ PRINCIPAL");
    System.out.println("1. Registrar Cuenta");
    System.out.println("2. Consultar Cuenta");
    System.out.println("3. Ver Cuentas");
    System.out.println("4. Ver Saldo Total");
    System.out.println("5. Aplicar Intereses");
    System.out.println("0. Salir");
}

La decisión sobre qué ejecutar pertenece al Controlador.

do {
    v.mostrarMenuPrincipal();
    opcion = v.pedirOpcion();

    switch (opcion) {
        case 1: registrar(); break;
        case 2: consultar(); break;
        case 3: verCuentas(); break;
        case 4: verSaldoTotal(); break;
        case 5: aplicarIntereses(); break;
    }
} while (opcion != 0);
Regla sencilla: la Vista muestra las opciones; el Controlador interpreta la opción y decide qué método ejecutar.

11. ¿Qué hace Main?

Main debe ser pequeño. Su responsabilidad es crear el controlador y arrancar la aplicación.

public class Main {
    public static void main(String[] args) {
        Controlador app = new Controlador();
        app.iniciar();
    }
}

A partir de app.iniciar(), el controlador prepara el vector, carga datos iniciales y mantiene activo el menú.

12. Resumen para recordar

Pregunta Respuesta
¿Dónde están los atributos de una cuenta? En el Modelo.
¿Quién usa Scanner? La Vista.
¿Dónde se imprime el menú? En la Vista.
¿Quién decide qué opción ejecutar? El Controlador.
¿Dónde está el vector? En el Controlador.
¿Qué indica registros? Cuántas posiciones del vector están ocupadas.
¿Cómo se agrega un objeto? cuentas[registros++] = cuenta;
¿Cómo se recorren los objetos existentes? Con un ciclo desde 0 hasta registros - 1.
MVC no significa tener simplemente tres clases. Lo importante es separar responsabilidades: el modelo representa los datos, la vista se comunica con el usuario y el controlador coordina el flujo y administra los objetos.
