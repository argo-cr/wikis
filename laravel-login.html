BASE DE DATOS

¿Qué guarda la tabla usuarios?

La misma tabla permite trabajar con cuentas locales y cuentas de Google. La diferencia está en qué campos se utilizan para autenticar a cada persona.

Campo Autenticación local Autenticación Google
id_usuario ID autoincremental ID autoincremental
nombre Lo ingresa el usuario Lo devuelve Google
correo Correo registrado (único) Correo devuelto por Google
user Nombre para iniciar sesión Puede ser NULL
password Hash de la contraseña Puede ser NULL
imagen Puede ser NULL: imagen por defecto Avatar de Google
google_id NULL inicialmente ID único de Google
Dos formas de autenticarse, una sola sesión

En el login local, Laravel verifica user y password con Auth::attempt(). Con Google, Socialite recupera la identidad y Laravel inicia la sesión mediante Auth::login($user).

public/sql/db_laravel_login.sql · estructura relevante
CREATE TABLE usuarios (
    id_usuario INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    correo VARCHAR(150) NOT NULL UNIQUE,
    user VARCHAR(50) UNIQUE,
    password VARCHAR(255),
    imagen VARCHAR(500),
    google_id VARCHAR(255) UNIQUE
);

01

Adaptar el modelo User

El modelo original espera una tabla llamada users. Nuestra tabla se llama usuarios y su clave primaria es id_usuario. Dentro de la clase User, agrega estas propiedades y métodos:

app/Models/User.php · dentro de class User
protected $table = 'usuarios';
protected $primaryKey = 'id_usuario';
public $timestamps = false;

public function comentarios()
{
    return $this->hasMany(Comentario::class, 'id_usuario');
}

public function imagen()
{
    return $this->imagen ?: asset('theme/assets/img/user.png');
}

Conserva la herencia extends Authenticatable. La relación comentarios() se utilizará más adelante.

03

Implementar el registro local

Dentro de ControllerAuth agrega el método register(). Se mantiene el estilo del proyecto: crear un objeto, asignar propiedades y guardarlo.

ControllerAuth.php · método nuevo
public function register(Request $request)
{
    $request->validate([
        'nombre' => 'required',
        'correo' => 'required|email|unique:usuarios,correo',
        'user' => 'required|unique:usuarios,user',
        'password' => 'required|confirmed'
    ]);

    $user = new User();
    $user->nombre = $request->nombre;
    $user->correo = $request->correo;
    $user->user = $request->user;
    $user->password = Hash::make($request->password);
    $user->save();

    return redirect()->route('login');
}

confirmed requiere un input llamado password_confirmation. El correo también debe ser único porque la base de datos lo exige.

04

Implementar el login

El usuario ingresa con su nombre de usuario, no con el correo electrónico.

ControllerAuth.php · método nuevo
public function login(Request $request)
{
    $datos = [
        'user' => $request->user,
        'password' => $request->password
    ];

    if (Auth::attempt($datos)) {
        $request->session()->regenerate();
        return redirect()->route('dashboard');
    }

    return back()->withErrors([
        'login' => 'Usuario o contraseña incorrectos'
    ])->onlyInput('user');
}

Auth::attempt() verifica el hash almacenado. Si las credenciales son válidas, Laravel crea la sesión y la regeneramos para reducir el riesgo de fijación de sesión.

05

Implementar el logout

ControllerAuth.php · método nuevo
public function logout(Request $request)
{
    Auth::logout();
    $request->session()->invalidate();
    $request->session()->regenerateToken();

    return redirect()->route('login');
}

El logout elimina la autenticación, invalida la sesión y renueva el token CSRF.

06

Configurar rutas públicas y privadas

En el proyecto base, las rutas todavía son públicas. Reorganízalas así:

routes/web.php · reemplazar rutas anteriores
use App\Http\Controllers\ControllerAuth;
use App\Http\Controllers\ControllerComentarios;
use App\Http\Controllers\ControllerNavigation;
use Illuminate\Support\Facades\Route;

Route::middleware('guest')->group(function () {
    Route::get('/login', [ControllerNavigation::class, 'login'])->name('login');
    Route::get('/register', [ControllerNavigation::class, 'register'])->name('register');
    Route::post('/login', [ControllerAuth::class, 'login']);
    Route::post('/register', [ControllerAuth::class, 'register']);
});

Route::middleware('auth')->group(function () {
    Route::get('/', [ControllerNavigation::class, 'dashboard'])->name('dashboard');
    Route::resource('comentarios', ControllerComentarios::class);
    Route::post('/logout', [ControllerAuth::class, 'logout'])->name('logout');
});
Diferencia importante

guest permite acceder solo a visitantes sin sesión; auth exige una sesión iniciada.

Ahora puedes reemplazar el nombre e imagen ficticios en el listado reciente:

Permisos de los comentarios

Filtrar el listado no impide editar o eliminar un comentario ajeno si se conoce su URL. Para un sistema real, agrega una verificación de propiedad en edit(), update() y destroy(), por ejemplo abort_unless($comentario->id_usuario === Auth::id(), 403);.

¿Qué vamos a configurar?

No necesitamos una clave de API de Gemini. Necesitamos un cliente OAuth 2.0 de tipo Aplicación web para permitir que Google devuelva al usuario a Laravel.

Abre Google Auth Platform → Vista general ↗. Si aparece Comenzar, completa el asistente inicial. Los nombres pueden variar ligeramente según el idioma de la consola.

① Información de la aplicación

En Branding / Información de la marca ↗, define nombre «Laravel Login», correo de soporte y correo de contacto.

② Público

En Público / Audience ↗, selecciona Externo. Mantén el estado de prueba durante el laboratorio.

③ Usuarios de prueba

En la misma pantalla Público, agrega las direcciones Gmail que utilizarán la aplicación mientras esté en pruebas.

Sobre el modo de prueba

En el estado de prueba, los usuarios no agregados a la lista pueden recibir un bloqueo de acceso. Si el grupo es grande, cada estudiante puede crear sus propias credenciales de laboratorio.

15

Crear el cliente OAuth web

Entra a Google Auth Platform → Clientes ↗ y presiona Crear cliente.

Tipo de aplicaciónAplicación web
NombreLaravel Local
Orígenes JavaScriptDejar vacío (no se requiere en este flujo)
URI de redireccionamiento autorizadohttp://localhost:8000/auth/google/callback

Haz clic en Agregar URI, pega la dirección exacta y luego presiona Crear. Google mostrará el Client ID y el Client Secret.

Coincidencia exacta

El callback debe coincidir exactamente con la URL autorizada, incluido protocolo, host, puerto y ruta. Si usas localhost en Google, abre Laravel también con localhost, no con 127.0.0.1.

Agregar los métodos de Google al controlador

El proyecto final utiliza Laravel\Socialite\Socialite. Conservaremos ese estilo. En ControllerAuth agrega:

ControllerAuth.php · import
use Laravel\Socialite\Socialite;
ControllerAuth.php · método nuevo
public function redirectGoogle()
{
    return Socialite::driver('google')->redirect();
}

En el callback obtenemos la cuenta autorizada, buscamos el usuario por google_id y creamos una cuenta si todavía no existe:

ControllerAuth.php · método nuevo (flujo recomendado)
public function callbackGoogle(Request $request)
{
    $googleUser = Socialite::driver('google')->user();

    $user = User::where('google_id', $googleUser->getId())->first();

    if (!$user) {
        // Evitar vincular automáticamente una cuenta local por correo.
        if (User::where('correo', $googleUser->getEmail())->exists()) {
            return redirect()->route('login')->withErrors([
                'google' => 'Este correo ya tiene una cuenta local. Inicia sesión y vincula Google desde tu perfil.'
            ]);
        }

        $user = new User();
        $user->nombre = $googleUser->getName();
        $user->correo = $googleUser->getEmail();
        $user->imagen = $googleUser->getAvatar();
        $user->google_id = $googleUser->getId();
        $user->save();
    }

    Auth::login($user);
    $request->session()->regenerate();

    return redirect()->route('dashboard');
}

La versión de referencia final busca también por correo y vincula automáticamente la cuenta local. En esta wiki evitamos esa vinculación automática: si el correo ya existe, se pide iniciar sesión localmente. La vinculación verificada puede desarrollarse como una mejora posterior.

AYUDA RÁPIDA

Errores frecuentes

Si Google no permite completar el acceso, revisa estas causas antes de modificar el código.

redirect_uri_mismatch

La URL configurada en Google Cloud no coincide con GOOGLE_REDIRECT_URI. Verifica protocolo, localhost, puerto 8000 y /auth/google/callback.

access_denied o aplicación en pruebas

Revisa Público → Usuarios de prueba en Google Auth Platform y confirma que la cuenta esté autorizada.

InvalidStateException

Verifica que la sesión de Laravel funcione, que las cookies estén habilitadas y que no cambies entre localhost y 127.0.0.1 durante el flujo.

Google no encuentra las credenciales

Revisa las tres variables de .env, el bloque google de config/services.php y ejecuta php artisan config:clear.

El usuario no puede iniciar sesión localmente después de registrarse con Google

Es normal: una cuenta creada solo mediante Google no tiene contraseña local. Para habilitar ambos métodos necesitarías un flujo adicional para establecer contraseña o vincular cuentas.

CIERRE DEL LABORATORIO

¿Qué aprendimos?

Los dos métodos de acceso terminan utilizando la autenticación de Laravel, pero verifican la identidad de maneras diferentes.

Aspecto Login local Google
Identidad Usuario + contraseña Cuenta autorizada por Google
Método principal Auth::attempt() Auth::login($user)
Contraseña Hash::make() No se almacena una contraseña de Google
Tabla usuarios usuarios
Sesión y rutas Se comparten Auth, auth, guest y logout.

La autenticación se integra sobre la misma aplicación. El Dashboard y los comentarios siguen funcionando sin importar el método de ingreso.
