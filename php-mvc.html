La idea de MVC

MVC divide la aplicación en tres responsabilidades principales. No es una tecnología adicional: es una forma ordenada de distribuir el código.

Modelo

Representa los datos y contiene las operaciones de acceso a la base de datos.

Vista

Presenta la información al usuario mediante HTML, PHP y componentes visuales.

Controlador

Recibe la solicitud, coordina el modelo y decide qué vista o acción ejecutar.

Regla sencilla: la vista muestra, el modelo trabaja con los datos y el controlador coordina.

Flujo de una petición

Cuando el usuario selecciona «Personas», el navegador envía parámetros a index.php. La aplicación sigue este recorrido:

Navegador→index.php→Controlador→Modelo→Vista

Por ejemplo, para listar personas, el controlador llama a Persona::all(), recibe un arreglo de objetos y carga la vista enviándole ese resultado en la variable $data.

Las rutas de index.php

Este archivo centraliza las solicitudes. Primero obtiene route y action; después utiliza switch para decidir qué método ejecutar.

index.php
$route = $_GET['route'] ?? '';
$action = $_GET['action'] ?? 'index';

switch ($route) {
    case 'personas':
        $controller = new ControllerPersonas();

        switch ($action) {
            case 'index':   $controller->index(); break;
            case 'create':  $controller->create(); break;
            case 'edit':    $controller->edit($_GET['id']); break;
            case 'show':    $controller->show($_GET['id']); break;
            case 'store':   $controller->store($_POST); break;
            case 'update':  $controller->update($_POST, $_GET['id']); break;
            case 'destroy': $controller->destroy($_GET['id']); break;
        }
        break;
    default:
        (new ControllerNavigation())->dashboard();
}
URL Resultado
index.php Dashboard
?route=personas Lista de personas
?route=personas&action=create Formulario de registro
?route=personas&action=edit&id=3 Formulario de edición
?route=personas&action=show&id=3 Detalle de una persona

El modelo: Persona.php

El modelo representa una persona y conoce cómo guardarla, consultarla, actualizarla o eliminarla. El controlador no debería contener instrucciones SQL.

app/models/Persona.php
class Persona {
    private static $conn;
    public $id;
    public $nombre;
    public $edad;

    public static function all() {
        self::init();
        $stmt = self::$conn->prepare('SELECT * FROM personas');
        $stmt->execute();
        // Convertir cada fila en un objeto Persona
        return $data;
    }

    public function save() {
        $sql = 'INSERT INTO personas (nombre, edad)
                VALUES (:nombre, :edad)';
        return self::$conn->prepare($sql)->execute([
            ':nombre' => $this->nombre,
            ':edad' => $this->edad
        ]);
    }
}

Métodos del modelo Persona

El modelo Persona.php contiene métodos para establecer la conexión, consultar registros y ejecutar las operaciones CRUD.

Método Tipo Descripción
__construct() Instancia Se ejecuta al crear un objeto Persona y llama a init().
init() Estático Inicializa la conexión con la base de datos solamente cuando todavía no existe.
all() Estático Consulta todas las personas y devuelve un arreglo de objetos Persona.
find($id) Estático Busca una persona utilizando su identificador.
save() Instancia Guarda en la base de datos la información del objeto actual.
update() Instancia Actualiza los datos de la persona representada por el objeto actual.
delete() Instancia Elimina de la base de datos la persona representada por el objeto actual.

self y static

En PHP, self y static se utilizan principalmente cuando trabajamos con propiedades y métodos estáticos.

self

Hace referencia a la clase en la que se encuentra escrito el código. En este caso, self representa a la clase Persona.

static

Indica que una propiedad o método pertenece a la clase y no a un objeto específico. Puede utilizarse sin crear una instancia.

Utilizar una propiedad estática

Persona.php
private static $conn;

self::$conn = $database->getConnection();

La propiedad $conn es estática porque la conexión puede ser compartida por todos los métodos del modelo. Para acceder a ella desde la misma clase se utiliza self::$conn.

Utilizar un método estático

Desde el controlador
$data = Persona::all();

$item = Persona::find($id);

El operador :: permite llamar métodos estáticos directamente desde la clase, sin crear primero un objeto.

Comparación rápida

// Método estático: se llama desde la clase
$data = Persona::all();

// Método de instancia: requiere un objeto
$item = new Persona();
$item->nombre = 'Ana';
$item->edad =  20;
$item->save();
Idea clave: Persona::all() utiliza un método estático porque consulta una colección completa. En cambio, $item->save() utiliza un método de instancia porque guarda los datos de un objeto específico.

El controlador

ControllerPersonas contiene dos grupos de métodos: los que cargan vistas y los que ejecutan acciones.

Vistas

index(), create(), edit($id) y show($id).

Acciones

store(), update() y destroy(). Reciben datos del formulario y llaman al modelo.

ControllerPersonas.php
public function index() {
    $data = Persona::all();
    include 'app/views/modules/personas/index.php';
}

public function store($request) {
    $item = new Persona();
    $item->nombre = $request['nombre'];
    $item->edad = $request['edad'];
    $item->save();
    $this->go_home();
}

Después de guardar, go_home() redirige a la lista. Esto evita que al actualizar el navegador se repita el envío del formulario.

Las vistas y el layout

Las vistas están agrupadas por módulo. Cada página incluye un encabezado común y un pie común:

<?php include 'app/views/layout/header.php'; ?>

<!-- Contenido propio de la vista -->
<h1>Lista de Personas</h1>

<?php include 'app/views/layout/footer.php'; ?>

En index.php de Personas, la variable $data contiene los objetos recuperados por el modelo:

<?php foreach ($data as $item) { ?>
    <tr>
        <td><?= $item->id ?></td>
        <td><?= $item->nombre ?></td>
        <td><?= $item->edad ?></td>
    </tr>
<?php } ?>
Idea importante: una vista puede mostrar datos, pero no debería decidir cómo consultarlos ni contener la lógica completa del negocio.

Carpetas de servicio

Contiene configuraciones reutilizables. Database.php crea la conexión PDO a MySQL.

public/

Contiene CSS, JavaScript, imágenes, Bootstrap y respaldos SQL del ejemplo.

app/views/layout/

Guarda elementos visuales compartidos como menú, encabezado y pie de página.

config/Database.php
$this->conn = new PDO(
    'mysql:host=' . $this->host . ';dbname=' . $this->db_name,
    $this->username,
    $this->password
);
$this->conn->exec('set names utf8');

Buenas prácticas para continuar

✓ Una responsabilidad por archivo.

✓ El SQL permanece en el modelo.

✓ El controlador coordina, pero no diseña la interfaz.

✓ Las vistas muestran datos y reciben eventos del usuario.

✓ Usar require_once para clases necesarias.

✓ Validar campos antes de guardar.

✓ Escapar valores al imprimirlos con htmlspecialchars().

✓ Proteger la eliminación con POST y una confirmación.

Reto sugerido: agregar un campo correo a Personas. El estudiante debe modificar la tabla, el modelo, los formularios, la lista, el detalle y las operaciones de guardar/actualizar.
