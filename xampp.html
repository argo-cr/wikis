XAMPP portable, Server Root y Virtual Hosts

Configure un entorno de desarrollo en Windows a partir del archivo ZIP de XAMPP y asigne dominios locales independientes a sus proyectos.

WindowsApachePHPVirtual HostsLaravel

1. Preparar XAMPP portable

La versión comprimida no requiere un instalador tradicional: se extrae y luego se ajustan sus rutas internas.

1

Descargar

Obtenga XAMPP para Windows desde Apache Friends. Verifique que la versión de PHP sea compatible con los proyectos del curso.

2

Descomprimir

Extraiga el contenido en una ruta corta y sin espacios.

Ruta recomendada
C:\xampp
Evite rutas protegidasNo utilice C:\Program Files\xampp. Los espacios y permisos de Windows pueden provocar errores.
3

Ajustar rutas internas

Desde la carpeta principal, ejecute:

Windows
C:\xampp\setup_xampp.bat

Repita este procedimiento si posteriormente mueve la carpeta completa.

4

Abrir el panel

Ejecute xampp-control.exe como administrador e inicie Apache y MySQL.

2. Realizar la primera prueba

Abra http://localhost. La carpeta pública predeterminada es C:\xampp\htdocs.

Cree C:\xampp\htdocs\prueba.php:

prueba.php
<?php
echo "XAMPP funciona correctamente";

Después visite http://localhost/prueba.php.

Resultado esperadoEl navegador muestra el mensaje sin descargar el archivo PHP ni presentar el código fuente.

3. Cambiar el Server Root

DocumentRoot es la carpeta que Apache publica cuando se visita localhost.

Cree una carpeta separada para los proyectos:

Estructura sugerida
C:\ProyectosWeb
├── proyecto1
├── proyecto2
└── proyecto3

Abra C:\xampp\apache\conf\httpd.conf y localice las dos referencias a htdocs:

httpd.conf
DocumentRoot "C:/ProyectosWeb"

<Directory "C:/ProyectosWeb">
    Options Indexes FollowSymLinks Includes ExecCGI
    AllowOverride All
    Require all granted
</Directory>
Importante sobre las rutasEn la configuración de Apache utilice barras inclinadas C:/ProyectosWeb, aunque Windows normalmente muestre barras invertidas.

Guarde el archivo, detenga Apache y vuelva a iniciarlo.

4. Configurar Virtual Hosts

Un Virtual Host asigna un nombre local a cada proyecto. Así, localhost/proyecto1 puede convertirse en proyecto1.local.

4.1 Habilitar el archivo de Virtual Hosts

En httpd.conf, asegúrese de que esta línea no tenga # al inicio:

httpd.conf
Include conf/extra/httpd-vhosts.conf

4.2 Conservar localhost

Abra C:\xampp\apache\conf\extra\httpd-vhosts.conf y agregue:

httpd-vhosts.conf
<VirtualHost *:80>
    ServerName localhost
    DocumentRoot "C:/ProyectosWeb"

    <Directory "C:/ProyectosWeb">
        Options Indexes FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>

4.3 Registrar el proyecto

httpd-vhosts.conf
<VirtualHost *:80>
    ServerName proyecto1.local
    DocumentRoot "C:/ProyectosWeb/proyecto1"

    <Directory "C:/ProyectosWeb/proyecto1">
        Options Indexes FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>

    ErrorLog "logs/proyecto1-error.log"
    CustomLog "logs/proyecto1-access.log" common
</VirtualHost>
DirectivaFunción
ServerNameNombre de dominio local.
DocumentRootCarpeta pública del proyecto.
AllowOverride AllPermite reglas mediante .htaccess.
Require all grantedAutoriza el acceso a la carpeta.
ErrorLogRegistra errores propios del sitio.

5. Registrar el dominio en Windows

Apache conoce el sitio, pero Windows aún debe saber que el dominio apunta a la computadora local.

  1. Abra el Bloc de notas como administrador.
  2. Seleccione Archivo → Abrir.
  3. Abra C:\Windows\System32\drivers\etc\hosts.
  4. Si no aparece, cambie el filtro a Todos los archivos.
  5. Agregue las siguientes líneas y guarde:
hosts
127.0.0.1 localhost
127.0.0.1 proyecto1.local

Reinicie Apache y visite http://proyecto1.local.

Si Windows conserva una dirección anteriorAbra una consola y ejecute ipconfig /flushdns.

6. Proyectos con carpeta public

Laravel y otros frameworks poseen una carpeta pública. El dominio debe apuntar a ella, no a la raíz completa del proyecto.

Virtual Host para Laravel
<VirtualHost *:80>
    ServerName mi-laravel.local
    DocumentRoot "C:/ProyectosWeb/mi-laravel/public"

    <Directory "C:/ProyectosWeb/mi-laravel/public">
        Options Indexes FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>

    ErrorLog "logs/mi-laravel-error.log"
    CustomLog "logs/mi-laravel-access.log" common
</VirtualHost>
Razón de seguridadApuntar a la raíz de Laravel puede exponer archivos de configuración y otras partes internas de la aplicación.

7. Validar antes de reiniciar

Abra CMD y cambie al directorio de Apache:

CMD
cd C:\xampp\apache\bin
httpd.exe -t

La respuesta correcta es:

Resultado esperado
Syntax OK

Para consultar todos los dominios que Apache reconoce:

CMD
httpd.exe -S

Errores frecuentes

Apache no inicia

  • Existe un error de sintaxis: ejecute httpd.exe -t.
  • El puerto 80 está ocupado por otra aplicación.
  • La ruta indicada no existe.
  • Falta cerrar </VirtualHost> o </Directory>.
  • XAMPP fue movido y no se volvió a ejecutar setup_xampp.bat.

Consulte también C:\xampp\apache\logs\error.log.

403 Forbidden

Compruebe que el bloque Directory corresponda exactamente con la ruta y contenga Require all granted.

El dominio abre otro proyecto

Apache suele mostrar el primer Virtual Host cuando el dominio solicitado no coincide con ninguno. Compare ServerName, el archivo hosts y el resultado de httpd.exe -S.

Apache utiliza el puerto 8080

Cambie a <VirtualHost *:8080> e ingrese mediante http://proyecto1.local:8080.

Práctica de clase

Configure dos proyectos independientes y compruebe que ambos dominios funcionan.

1. Crear carpetas
2. Crear VHosts
3. Editar hosts
4. Validar y probar
Carpetas y dominios
C:\ProyectosWeb\facturacion  →  http://facturacion.local
C:\ProyectosWeb\inventario   →  http://inventario.local

Cada carpeta debe contener un index.php que identifique el proyecto. Cada Virtual Host debe incluir ServerName, DocumentRoot, bloque Directory, acceso a .htaccess y archivo de errores independiente.

Criterio de finalizaciónEl comando httpd.exe -t devuelve Syntax OK y ambos dominios cargan el proyecto correcto.

Lista de comprobación

  • Descomprimir XAMPP en una ruta corta.
  • Ejecutar setup_xampp.bat.
  • Iniciar Apache y MySQL.
  • Crear la carpeta general de proyectos.
  • Configurar el DocumentRoot.
  • Habilitar httpd-vhosts.conf.
  • Crear un bloque VirtualHost por proyecto.
  • Registrar cada dominio en el archivo hosts.
  • Validar mediante httpd.exe -t.
  • Reiniciar Apache y probar desde el navegador.
