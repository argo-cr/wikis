PASO 03

Conexión con IndexedDB

Creamos la base de datos db_personas y el almacén personas.

En js/app.js, ubica el comentario //--------- DB --------- y agrega:

¿Qué es IndexedDB y de dónde viene? IndexedDB es una API estándar de los navegadores web (Web API), accesible desde JavaScript mediante window.indexedDB. No es una biblioteca externa, no se instala con npm y no requiere MySQL ni un servidor de base de datos. Guarda objetos estructurados en el almacenamiento del navegador, asociados al origen (protocolo + dominio + puerto) de la página.

Conceptos antes de programar

Base de datos: contenedor db_personas. Object store: colección personas, comparable a una tabla. Clave: identifica cada registro. Transacción: agrupa operaciones sobre un almacén; puede ser readonly o readwrite. Solicitud: una operación asíncrona cuyo resultado se obtiene mediante eventos como onsuccess y onerror.

Inspeccionar IndexedDB desde Chrome

  1. Abre la aplicación con Live Server y presiona F12.
  2. Entra en Application → Storage → IndexedDB (puede aparecer simplemente como IndexedDB).
  3. Expande db_personas y el almacén personas; selecciona el almacén para revisar las filas y sus claves.
  4. Registra o elimina una persona y utiliza el botón de actualizar del panel para observar los cambios.
  5. Para reiniciar la práctica, puedes eliminar la base desde el menú contextual de db_personas o usar Application → Storage → Clear site data. Esto elimina datos del sitio; úsalo con cuidado.

En la consola también puedes ejecutar indexedDB.databases() en navegadores compatibles para listar las bases del origen. El panel Application es la forma más visual para la clase.

js/app.js · DB
let db;
conexion();

function conexion() {
  const solicitud = indexedDB.open("db_personas", 1);

  solicitud.onupgradeneeded = function (event) {
    db = event.target.result;

    db.createObjectStore("personas", {
      keyPath: "id",
      autoIncrement: true,
    });
  };

  solicitud.onsuccess = function (event) {
    db = event.target.result;
    loadTable();
  };

  solicitud.onerror = function () {
    console.log("Error al abrir la base de datos");
  };
}

indexedDB.open() abre o crea la base. onupgradeneeded define el almacén; onsuccess conserva la conexión y carga la tabla. La clave id se genera automáticamente.

PASO 04

Implementación del CRUD

Completa las cinco funciones vacías del archivo js/app.js.

store()

Agrega una persona usando una transacción de lectura y escritura.

¿Por qué las operaciones son asíncronas?

IndexedDB no devuelve los datos inmediatamente: inicia una solicitud y comunica su resultado más tarde, sin bloquear la interfaz. Por eso el código utiliza eventos como tx.oncomplete y, para las consultas, promesas.

Promesa (Promise): objeto que representa un resultado futuro. Puede estar pendiente, resuelta (con un valor) o rechazada (con un error). resolve(valor) entrega el resultado y reject(error) informa del fallo. .then() y .catch() permiten procesarlos.

async se coloca delante de una función para que devuelva una promesa. await se usa dentro de una función async para esperar el resultado de otra promesa, sin congelar el navegador. No convierte automáticamente las solicitudes de IndexedDB en promesas: para ello el proyecto las envuelve con new Promise(...).

Ejemplo didáctico · async y await (no agregar al proyecto)
function obtenerNombre() {
  return Promise.resolve("Ana");
}

async function mostrarNombre() {
  const nombre = await obtenerNombre();
  console.log(nombre); // Ana
}

mostrarNombre();

En las funciones de consulta del proyecto, observa cómo request.onsuccess llama a resolve(request.result). Cuando se ejecuta await all() o await find(id), JavaScript espera esa resolución. En cambio, tx.oncomplete se usa para actualizar la interfaz solo después de finalizar la escritura.

js/app.js · store()
function store(item) {
  const tx = db.transaction("personas", "readwrite");
  const personas = tx.objectStore("personas");
  personas.add(item);

  tx.oncomplete = function () {
    clearForm();
    loadTable();
    notificar("Registrado: " + item.nombre);
  };
}

update()

Actualiza un registro existente mediante put().

js/app.js · update()
function update(item) {
  const tx = db.transaction("personas", "readwrite");
  const personas = tx.objectStore("personas");

  personas.put(item);

  tx.oncomplete = function () {
    clearForm();
    loadTable();
    notificar("Actualizado: " + item.nombre);
  };
}

destroy()

Confirma la eliminación y borra el registro por su identificador.

js/app.js · destroy()
function destroy(id) {
  if (!confirm("¿Desea eliminar este registro?")) {
    return;
  }

  const tx = db.transaction("personas", "readwrite");
  const personas = tx.objectStore("personas");

  personas.delete(id);

  tx.oncomplete = function () {
    loadTable();
    notificar("Registro Eliminado: ");
  };
}

all()

Obtiene todos los registros y devuelve una promesa.

js/app.js · all()
function all() {
  return new Promise(function (resolve, reject) {
    const tx = db.transaction("personas", "readonly");
    const personas = tx.objectStore("personas");

    const solicitud = personas.getAll();

    solicitud.onsuccess = function () {
      resolve(solicitud.result);
    };

    solicitud.onerror = function () {
      reject(solicitud.error);
    };
  });
}

find()

Consulta una persona por su identificador y devuelve una promesa.

js/app.js · find()
function find(id) {
  return new Promise(function (resolve, reject) {
    const tx = db.transaction("personas", "readonly");
    const personas = tx.objectStore("personas");

    const solicitud = personas.get(id);

    solicitud.onsuccess = function () {
      resolve(solicitud.result);
    };

    solicitud.onerror = function () {
      reject(solicitud.error);
    };
  });
}
En el proyecto final, find() queda disponible aunque no se invoque desde los eventos actuales. El mensaje de eliminación es genérico, tal como está en el demo.

¿Qué hace exactamente await all()?

all() inicia una consulta a IndexedDB y devuelve una promesa con los registros. await espera a que esa promesa se resuelva y asigna el arreglo resultante a data. La función que contiene esa línea debe estar declarada como async. Si se omite await, data contendrá la promesa, no la lista de personas.

js/app.js · loadTable()
const data = await all();

La función loadTable() ya está declarada con async y el resto de su contenido permanece en el proyecto base. No es necesario reescribirla.

PASO 07

Registrar el Service Worker

El navegador registra sw.js desde la raíz de la aplicación.

Al final de index.html, dentro del bloque <script> que contiene //--------- PWA CONFIG ---------, agrega:

¿Qué es un Service Worker? Es un script JavaScript que el navegador ejecuta en un contexto separado de la página. Se registra mediante la API navigator.serviceWorker, que forma parte de la plataforma web. No puede manipular directamente el DOM ni acceder a variables de app.js. Puede responder a eventos como notificationclick y, si se implementan, fetch, install o activate.

register('/sw.js'): solicita al navegador registrar el script. navigator.serviceWorker.ready: devuelve una promesa que se resuelve cuando hay un registro activo que cubre la página. Scope (alcance): determina qué URLs controla; al ubicar sw.js en la raíz, su alcance predeterminado es /.

Inspeccionar, actualizar y desinstalar el Service Worker

  1. En Chrome abre F12 → Application → Service Workers.
  2. Comprueba el estado del registro, el archivo sw.js y su scope.
  3. Usa Update para buscar una versión nueva o Unregister para desregistrarlo durante las pruebas.
  4. Después de desregistrarlo, recarga la página. Si tu código todavía contiene register('/sw.js'), se registrará de nuevo; quita esa llamada si deseas retirarlo definitivamente.
Consola · desregistrar Service Workers del origen (solo diagnóstico)
const registros = await navigator.serviceWorker.getRegistrations();
await Promise.all(registros.map(registro => registro.unregister()));
console.log("Registros desinstalados");

Este comando afecta los registros del origen actual, no los de otros dominios. Desregistrar el Service Worker no borra automáticamente los datos de IndexedDB. Si quieres reiniciar por completo el sitio, utiliza Application → Storage → Clear site data y revisa las opciones seleccionadas.

index.html · PWA CONFIG
if ("serviceWorker" in navigator) {
        window.addEventListener("load", () => {
          initServiceWorker();
        });
      }

      function initServiceWorker() {
        navigator.serviceWorker
          .register("/sw.js")
          .then(() => console.log("Service worker is registered successfully"))
          .catch((error) =>
            console.error(`failed to register service worker, error: ${error}`),
          );
      }

La ruta /sw.js le permite al Service Worker tener alcance sobre la raíz. No se agregan eventos fetch ni mecanismos de caché.

✓
Comprobación

En DevTools → Application → Service Workers aparece el registro activo de /sw.js.

PASO 08

Notificaciones y clic

El Service Worker atiende el clic; la página solicita mostrar la notificación.

En sw.js, que está prácticamente vacío en el proyecto base, agrega:

Entender los métodos de notificaciones

Notification.requestPermission(): solicita autorización, preferiblemente a partir de un clic del usuario. navigator.serviceWorker.ready: espera un registro activo. registro.showNotification(titulo, opciones): pide al sistema mostrar una notificación. notificationclick: se ejecuta en el Service Worker cuando el usuario hace clic en ella. event.waitUntil(...): indica al navegador que debe permitir completar la operación asíncrona asociada al evento.

En este laboratorio se muestran notificaciones locales mientras se utiliza la aplicación; no se implementan suscripciones Push API ni un servidor para enviar notificaciones remotas. En iPhone, las notificaciones web tienen restricciones adicionales y no se garantiza el mismo comportamiento que en Windows.

sw.js
self.addEventListener("notificationclick", function (event) {
    event.notification.close();
    event.waitUntil(
        clients.openWindow("/")
    );
});

En js/app.js, bajo //--------- NOTIFICACIONES ---------, agrega la función:

js/app.js · notificar()
async function notificar(mensaje) {
    try {
        if (Notification.permission !== "granted") return;

        const registro = await navigator.serviceWorker.ready;

        await registro.showNotification("Personas PWA", {
            body: mensaje,
            icon: "/icons/icon512_rounded.png"
        });

    } catch (error) {
        console.error("Error al notificar:", error);
    }
}

Finalmente, completa el evento ya existente del botón de prueba con la llamada siguiente:

js/app.js · #btn-test-notification
notificar("Esta es una notificación de prueba");
Permisos: el demo únicamente muestra notificaciones cuando Notification.permission === "granted". Debes conceder el permiso al sitio previamente; esta guía no añade un flujo de solicitud de permiso porque no forma parte de las diferencias entre los ZIP. En iPhone, las notificaciones web tienen restricciones adicionales y no son un requisito de esta práctica.

PASO 09

Estado de conexión

Mostrar si el navegador detecta conexión mediante navigator.onLine.

En js/app.js, debajo de //--------- STATUS CONEXION ---------, agrega:

navigator.onLine es una propiedad booleana que refleja la conectividad estimada del navegador. Los eventos online y offline notifican cambios en esa estimación. No comprueban que el servidor Live Server o Cloudflare esté disponible y no activan por sí solos el funcionamiento offline.

js/app.js · conexión
$(document).ready(function () {
  showConnectivityStatus();
});

function showConnectivityStatus() {
  let isOnline = navigator.onLine;
  let status = $("#onlineStatus");

  if (!isOnline) {
    status.html("Offline");
  }

  window.addEventListener("online", () => {
    status.html("Online.");
    isOnline = true;
  });

  window.addEventListener("offline", () => {
    status.html("Offline.");
    isOnline = false;
  });
}
navigator.onLine es una señal orientativa de conectividad: no confirma que Live Server o Cloudflare estén disponibles. El demo no permite navegar offline si el HTML no está disponible.
✓
Comprobación

Prueba el estado de conexión desactivando temporalmente la red. La indicación puede variar según el navegador y el sistema.

PASO 11

Cloudflare Tunnel para móviles

Publica temporalmente Live Server mediante una URL HTTPS sin configurar un dominio propio.

1. En Windows, abre PowerShell e instala cloudflared:

PowerShell · instalación
winget install --id Cloudflare.cloudflared -e

2. Reinicia la terminal y verifica:

PowerShell · comprobación
cloudflared --version

3. Con Live Server ejecutándose en el puerto 5500, abre otra terminal:

PowerShell · túnel temporal
cloudflared tunnel --url http://localhost:5500

4. Copia la dirección https://...trycloudflare.com que aparezca en la terminal y ábrela en el teléfono. Prueba el formulario y la instalación de la PWA.

Importante: conserva abiertas las terminales de Live Server y Cloudflare. La URL del túnel temporal cambia al reiniciarlo; IndexedDB y los permisos de notificaciones están asociados al origen, por lo que una URL nueva tiene almacenamiento y permisos independientes.
✓
Comprobación

Abre la aplicación desde otro dispositivo mediante HTTPS. Registra una persona y comprueba el funcionamiento del CRUD.
